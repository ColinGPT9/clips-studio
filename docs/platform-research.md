## Summary: the findings that change the design

| # | Finding | Decision for Clips Kitty |
|---|---|---|
| 1 | **Every ecosystem studied that loads extension code into its own process gives that code the host's full access, and most say so in writing.** VS Code: "The extension host has the same permissions as VS Code itself" ([runtime security](https://code.visualstudio.com/docs/configure/extensions/extension-runtime-security)). Obsidian: "cannot reliably restrict plugins" ([plugin security](https://obsidian.md/help/plugin-security)). Open WebUI: functions "execute arbitrary Python code on your server. This is by design" ([plugin docs](https://docs.openwebui.com/features/extensibility/plugin)). ComfyUI custom nodes, Blender add-ons, Home Assistant integrations, Node-RED nodes and all three game engines are the same. The only host-enforced model in the set is Zed's: Wasm extensions whose capabilities the host checks at each call ([capabilities](https://zed.dev/docs/extensions/capabilities.html)). | **Plugins never run inside the engine.** A pipeline plugin is a separate process that the engine starts with a job and that answers with data, the same shape as the existing render-worker child (`remote_render/worker.py:82-87`). The engine never imports, `exec`s or pip-installs plugin code. |
| 2 | **A separate process is a stability boundary, not a security boundary.** A child process runs with the user's rights unless the OS confines it ([security note, H1](platform/research-notes/security-third-party-code.md#hypotheses)), and Clips Kitty's local API has no authentication: any process on the machine can already read footage, delete clips and publish (`SECURITY.md`; `server/api.py:577-589`). Windows offers Job Objects (lifetime, memory, process count) at no cost to the user, and AppContainer (files, network, devices) at real engineering cost ([Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects); [AppContainer isolation](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation)). | **Label every permission honestly.** "Enforced" is used only for what the engine itself checks (which job data it hands a plugin, which plugin endpoints a plugin's token may call) and for OS limits actually applied. Filesystem, network and GPU access are "declared by the developer, not enforced". The install screen says that plugins run with the user's rights. |
| 3 | **Clips Kitty's pipelines already separate detection from rendering.** Detection ends at `find_clips(...) -> (list[ClipCandidate], list[Rejection])` (`analysis/fusion.py:54-70`); rendering is `_render_files(...)`, "NO database access and NO LLM call" (`core/pipeline.py:1123-1138`); every finished file passes through `_register_clip` (`core/pipeline.py:1563`), which accepts files it did not render (`core/pipeline.py:685-754`). Eklipse's and OpusClip's user-visible output is the same thing: ranked time ranges with a label, a score and a reason ([Eklipse note](platform/research-notes/eklipse.md); [OpusClip API](https://help.opus.pro/api-reference/overview)). | **The pipeline contract is "video in, scored and labelled time ranges out".** Clips Kitty cuts, frames, captions and registers them with its existing code. A plugin may also return finished files, which go through the same `_register_clip` funnel. |
| 4 | **A static index in Git costs nothing and works.** AUTOMATIC1111's extension index (one JSON per entry, PR-merged, CI-validated, stars refreshed daily: [repo](https://github.com/AUTOMATIC1111/stable-diffusion-webui-extensions)), HACS ([default lists](https://github.com/hacs/default)), Zed (submodule pinned to a commit: [publishing guide](https://zed.dev/docs/extensions/publishing/publishing-guide.html)), Kilo's marketplace monorepo ([repo](https://github.com/Kilo-Org/kilo-marketplace)) and ComfyUI's first two years all run this way. | **The registry is a folder of small metadata files, one per plugin, submitted by pull request; CI validates them and builds one static JSON index.** Each entry points at the developer's own repository at a tag and a full 40-character commit. No backend, no accounts, no hosting of plugin code. |
| 5 | **The index's CI is the attack surface.** Open VSX's Git-index auto-publisher ran third-party builds next to a token that could publish "under any namespace" (CVE-2025-6705, [Eclipse advisory](https://blogs.eclipse.org/post/mikaël-barbero/eclipse-open-vsx-registry-security-advisory)). | **Index CI reads metadata only.** It never clones-and-builds, installs or runs plugin code and holds no secret that can publish. |
| 6 | **Hand review does not scale and is not a security audit.** Obsidian cleared "over 2,300 queued submissions" only after switching to automatic per-version review on 2026-05-12, and "subsequent versions were not reviewed" before that ([future of plugins](https://obsidian.md/blog/future-of-plugins/)). Zed review takes weeks to months; HACS says months; Pinokio's "verified" track is one admin ([Zed](platform/research-notes/zed.md), [HACS](platform/research-notes/home-assistant-hacs.md), [Pinokio](platform/research-notes/pinokio.md) notes). Fab can afford full human review because it takes 12% of sales ([Fab publishing](https://dev.epicgames.com/documentation/en-us/fab/publishing-assets-for-sale-or-free-download-in-fab)). | **Automated checks from day one** (schema, pinned commit exists, licence present, compatibility range, banned patterns in the manifest), and nothing in the UI implies a human looked at the code. |
| 7 | **"Verified" means something different and small everywhere.** ComfyUI's badge means "not flagged"; Pinokio's means one admin reviewed it and the repo was transferred to his org; VS Code's means domain ownership plus six months; Hugging Face's "Verified" commit means a GPG signature ([ComfyUI](platform/research-notes/comfyui.md), [Pinokio](platform/research-notes/pinokio.md), [VS Code](platform/research-notes/vscode-openvsx.md), [Hugging Face](platform/research-notes/hugging-face.md) notes). | **No "Verified" label at launch.** Tiers say what actually happened: *Official* (ships with Clips Kitty), *Listed* (in the registry, automated checks passed, not reviewed by a person), *Installed from a link* (not in the registry), and *Blocked* (on the block list, will not run). |
| 8 | **Shared Python environments cause conflicts and supply-chain incidents, and Clips Kitty cannot have one anyway.** ComfyUI ships four pieces of machinery to repair a shared environment and banned runtime pip after the LLMVISION and Ultralytics incidents ([Jan 2025 update](https://blog.comfy.org/p/comfyui-2025-jan-security-update)); Open WebUI now tells production users to turn off its own runtime pip ([env reference](https://docs.openwebui.com/reference/env-configuration)). Clips Kitty's frozen build has no pip and cannot run `-m` (`requirements.txt:66-70`). | **Each plugin brings its own runtime** (an executable, or a script run by an interpreter the user chooses) and **the host provides the heavy parts over its API**: rendering, captions, registration, progress. Installing a plugin never runs a script from it. |
| 9 | **Model identity is solved upstream; storage is not.** Hugging Face pins by a full commit hash and shares unchanged files between revisions, but on Windows without symlink permission "a single file might be downloaded several times" ([cache docs](https://huggingface.co/docs/huggingface_hub/guides/manage-cache)); loaders can be code (CVE-2026-4372, [advisory](https://advisories.gitlab.com/pypi/transformers/CVE-2026-4372/)); pickle scanning has been bypassed ([JFrog](https://jfrog.com/blog/data-scientists-targeted-by-malicious-hugging-face-ml-models-with-silent-backdoor/)). Ollama pins by digest ([API](https://docs.ollama.com/api.md)). | **The model manager is an index over stores that already exist** (the Hugging Face cache, Ollama's store, Clips Kitty's bundled `vendor/` models), keyed by source and pinned revision, not a new store. Pickle formats are refused by default. |
| 10 | **Several implementations of one capability need a two-level catalogue and a record of what ran.** OpenRouter lists a model, then the providers that implement it, and reports which one served the request ([fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks.md)); Replicate generates a typed input/output schema per version ([versions](https://replicate.com/docs/topics/models/versions.md)). | **Plugin ids are `publisher/name`; each plugin declares the capability it implements (for example `highlight_detection`) with typed inputs and outputs; every clip records which plugin and version produced it.** |
| 11 | **The specialised gaming market is closed.** Eklipse sells per-game detection models and five genre configurations for $24.99 a month with no free clipping tier since 2026-06-01, and publishes no API, SDK or plugin system ([Eklipse note](platform/research-notes/eklipse.md)). Overwolf, the nearest per-game platform, approves apps through a proposal whitelist and its Developer Terms (updated 2025-10-09) give it 15% of subscription and 30% of ad revenue ([developer terms](https://legal.overwolf.com/docs/overwolf/developers/developer-terms)). Every other gaming clipper studied (Medal, Allstar, Sizzle, SteelSeries Moments, NVIDIA Highlights, Powder) is a closed product whose only extension point, where one exists, lets a *game studio* emit events, not a third party add a detector ([clippers note](platform/research-notes/gaming-clippers.md)). | **Route game → genre → generic.** A game pipeline from the community runs when it matches; Clips Kitty's own Gaming mode stays the generic fallback; the user can always override. |
| 12 | **Counts without telemetry come from the hosts.** A1111 refreshes GitHub stars daily; Node-RED shows npm downloads; Hugging Face counts downloads server-side ([notes](platform/research-notes/other-registries.md)). GlassWorm's counts were inflated by bots ([Eclipse, Oct 2025](https://blogs.eclipse.org/post/mikaël-barbero/open-vsx-security-update-october-2025)). | **Show GitHub stars and last-updated date captured at index build time; no telemetry.** Never present a count as a trust signal. |

**Answer to Track D's question.** A specialised gaming clipping product provides five things, every time: (1) an event source per game (a game's own data feed, replay or log parsing, or on-screen recognition of the HUD and kill feed, with vision and audio as the generic fallback); (2) a timing rule that turns an event into a clip (Overwolf's `past / future / pending` triple, NVIDIA's start and end deltas, Medal's `duration` and `captureDelayMs`); (3) routing from the game being played to the right detector, with a generic fallback (Eklipse: game → genre → generic; Sizzle and Powder: per-game models plus a "universal" mode); (4) a per-game status, because game patches break detectors (Overwolf's per-game event health page, Eklipse's "wrong game" help articles); and (5) an output of time ranges with event labels, which the product then renders. Clips Kitty already has (3)'s generic fallback, all of the rendering, and the job system. **Yes, independent developers can ship game-specific pipelines on it**: a pipeline plugin supplies (1) and (2) and returns (5); Clips Kitty supplies the rest. No product studied lets a third party do this today: Overwolf and Medal let a *game studio* emit events, Eklipse lets nobody in (inferred from the matrix).

## 7.3 What to borrow

Each section answers the brief's question for that platform, then names what to avoid and the decision it leads to. Detail and sources are in the linked note.

### ComfyUI: what should Clips Kitty borrow from its extension ecosystem? ([note](platform/research-notes/comfyui.md))

ComfyUI is the clearest case of an AI application that became an ecosystem, and its history shows both the cheap way in and the price paid later.

- **A very low floor.** A custom node pack is one folder, one manifest (`pyproject.toml` with `[project]` and `[tool.comfy]`: immutable `name`, semver `version`, `PublisherId`, a `requires-comfyui` range, OS and accelerator classifiers) and one entry point ([specifications](https://docs.comfy.org/registry/specifications.md)). Clips Kitty's manifest should be as small: id, publisher, version, compatibility range, entry point.
- **Immutable versions with a status per version.** Registry versions carry a status of `Pending`, `Active`, `Flagged`, `Banned` or `Deleted`, with a `deprecated` flag and a reason; the manager lists only active and pending ones ([registry OpenAPI](https://raw.githubusercontent.com/Comfy-Org/registry-backend/main/openapi.yml); [note §5, §7](platform/research-notes/comfyui.md)). That status describes what the registry did, not what the author is, which is the honest kind of trust signal.
- **Record the extension and version in every artefact.** ComfyUI writes `cnr_id` and `ver` into each node of a saved workflow, so "install missing nodes" works from a file ([note §5](platform/research-notes/comfyui.md)). Clips Kitty should record `publisher/name@version` on every clip a plugin produces.
- **Snapshots for rollback**: one JSON of the app version and every pack's version or commit, saved before "update all" and restorable ([note §5](platform/research-notes/comfyui.md)).
- **Start with a Git index.** ComfyUI ran for about two years on `custom-node-list.json` edited by pull request, a scanner that derived the node map, and stars fetched at build time; it broke down only on versioning and scanning ([note §6](platform/research-notes/comfyui.md)).
- **A startup block list** of known-bad packages, checked before anything loads (ComfyUI-Manager still blocks LLMVISION and the compromised `litellm` 1.82.7/8: [note §10](platform/research-notes/comfyui.md)).

**Avoid.** In-process Python with four code hooks (`requirements.txt`, `install.py`, `prestartup_script.py`, `__init__.py`): every incident on record used one of them (LLMVISION's custom wheels in 2024-06, the Ultralytics 8.3.41/42 miner in 2024-12: [ComfyUI statement](https://blog.comfy.org/p/comfyui-statement-on-the-ultralytics-crypto-miner-situation), dated 2024-12-05). A shared environment that plugins mutate. A badge that means "not flagged" but reads as "verified". Code-execution nodes on exposed instances, which a 2026-04 botnet campaign abused on more than 1,000 internet-facing servers ([Censys](https://censys.com/blog/comfyui-servers-cryptomining-proxy-botnet/), security-vendor research). A hosted registry as the only install path.

**Decision.** Copy the floor, immutable versions with a status, the artefact record, snapshots and the block list. Run plugins out of process and make the Git index the registry.

### Hugging Face: what should Clips Kitty borrow from model discovery and model metadata? ([note](platform/research-notes/hugging-face.md))

- **Reference models as `owner/name` at a full 40-character commit.** `HfApi.resolve_revision()` or `GET /api/models/{repo}/revision/{ref}` returns the `sha`; downloads take `revision=<sha>` ([download guide](https://huggingface.co/docs/huggingface_hub/guides/download)). Tags and branches can be moved or deleted, so they are not pins.
- **Read one metadata call before downloading.** `GET /api/models/{repo}?blobs=true&securityStatus=true` gives the licence, gated status, per-file sizes, commit and scan state in one anonymous request ([Hub API](https://huggingface.co/docs/hub/api)); the anonymous quota is per IP, so cache the answer under the commit.
- **Use the standard cache rather than a new store.** The cache shares unchanged files between revisions, but "symlinks are not supported on all machines. This is a known limitation especially on Windows", and without them a file "might be downloaded several times" ([cache guide](https://huggingface.co/docs/huggingface_hub/guides/manage-cache)). Detect this and tell the user, rather than silently disabling symlinks.
- **Surface the licence and gating before download** using the model card's `license` field (with `license_name`/`license_link` for `other`) and the gated prompt ([licenses](https://huggingface.co/docs/hub/repositories-licenses); [gated models](https://huggingface.co/docs/hub/models-gated)).
- **Prefer safetensors, ONNX and GGUF; refuse pickle by default.** The Hub's scanners label files but never block them, and have been bypassed (nullifAI in 2025; CVE-2026-56315 in picklescan), and a transformers loader turned a JSON config into code execution (CVE-2026-4372, [advisory](https://advisories.gitlab.com/pypi/transformers/CVE-2026-4372/)). Loading a model is running code, so it happens in the plugin's process, never in the engine's.
- **Remote inference on the user's own account.** Inference Providers expose an OpenAI-compatible router billed to the user's Hugging Face account ([note §9](platform/research-notes/hugging-face.md)); Clips Kitty's provider catalogue can add it as one `ProviderSpec` (`llm/providers/catalog.py:5-10`) without touching money.

**Avoid.** Mirroring or re-hosting model files, running a model registry, pinning to `main`, calling the search API per user action, treating a "safe" label or a GPG "Verified" commit as a safety review, and requiring a token for public models.

**Decision.** Model references in the manifest are `huggingface:owner/name@<40-hex sha>` plus the files needed; the model manager reads metadata first, downloads into the standard cache, refuses pickle unless the user confirms, and shows licence, size and gating before anything is fetched.

### OpenRouter: what should Clips Kitty borrow from a common interface over many implementations? ([note](platform/research-notes/openrouter.md))

- **A two-level catalogue.** `GET /api/v1/models` lists models with typed `input_modalities`, `output_modalities` and `supported_parameters`; `/models/{author}/{slug}/endpoints` lists the providers that implement each one ([models API](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)). For Clips Kitty the top level is a *capability* such as `highlight_detection` with a typed contract, and below it the plugins that implement it: Clips Kitty's own, Open Shorts', community A's, community B's, a remote API.
- **Typed request-time preferences**: `order`, `only`, `ignore`, `allow_fallbacks`, `require_parameters` ([provider selection](https://openrouter.ai/docs/guides/routing/provider-selection)).
- **An ordered fallback list that reports what actually ran.** "Requests are priced using the model that was ultimately used, which will be returned in the `model` attribute" ([fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks.md)).
- **Measured health beside declared policy**, labelled as such: uptime tiers are measured, data policies are "as reflected in each provider's terms" ([note §7](platform/research-notes/openrouter.md)).
- **Identifier grammar with a written resolution rule** (`author/slug[:variant]`) and honest lifecycle fields (`expiration_date`, deprecation warnings) ([model variants](https://openrouter.ai/docs/guides/routing/model-variants/overview.md)).

**Avoid.** A hosted catalogue service with gated onboarding, price-weighted routing (there are no prices here), and limiting "bring your own implementation" to a paid tier.

**Decision.** Each plugin declares the capability it implements; the job records which plugin and version produced each clip. Automatic routing and fallback between implementations is designed now and built later (the first release runs the one the user picked).

### Kilo Code: what should Clips Kitty borrow from its marketplace? ([note](platform/research-notes/kilo-code.md))

- **One metadata file per item in a Git monorepo, a generated index, strict validators.** `Kilo-Org/kilo-marketplace` keeps one `MCP.yaml`, `SKILL.md`, `AGENT_DEFINITION.md` or `PLUGIN.yaml` per item, accepts changes only by pull request, and generates `marketplace.yaml` per type in CI ([repo](https://github.com/Kilo-Org/kilo-marketplace)). Add what Kilo lacks: a version, a pinned commit and an index build date.
- **Install mechanics worth copying**: show scope, destination and prerequisites before writing anything; stage into a temporary sibling folder and rename atomically; inspect archives for links and path traversal before extracting; keep an ownership receipt per install so removal still works after the registry changes ([note §3](platform/research-notes/kilo-code.md)).
- **A git source grammar that cannot collide with other ids**, with a 40-hex commit treated as immutable ([note §3](platform/research-notes/kilo-code.md)).
- **Provenance fields and honest wording**: "Marketplace validation is not a security review"; "Plugins run code with full permissions" ([marketplace](https://kilo.ai/docs/customize/marketplace); [plugins](https://kilo.ai/docs/automate/extending/plugins)).
- **A mirror override** so a user or organisation can point the client at its own index.

**Avoid.** Mutable "latest" archives with no version (Kilo's `skills-latest`), vendoring third-party content into the registry (Kilo patches 64 of 191 vendored skills by hand), in-process plugins that can hook the permission prompts, flat ids, and "remove it first" in place of update ([note §12](platform/research-notes/kilo-code.md)). Kilo was acquired by Anaconda on 2026-07-15 with no visible change to the registry yet ([note §10](platform/research-notes/kilo-code.md), vendor press); a registry should not depend on one company's goodwill, which a static Git index anyone can fork avoids.

**Decision.** Copy the per-item metadata file, the generated index, the validators, the install dialog and receipt, and the wording. The registry holds metadata only and points at the developer's repository at a commit.

### Replicate: what should Clips Kitty borrow from model publishing and remote execution? ([note](platform/research-notes/replicate.md))

- **A typed, self-describing contract per version.** Cog derives an OpenAPI input and output schema from typed function arguments (`description`, `default`, `ge`, `le`, `choices`) ([cog.yaml](https://github.com/replicate/cog/blob/main/docs/yaml.md)). A Clips Kitty pipeline's settings and outputs should be declared the same way, so the app can render a settings form and validate results without running the plugin.
- **Hash-addressed versions** (`owner/name:version`, 64-hex) and the rule that an unversioned name is allowed only for the platform's own maintained models ([versions](https://replicate.com/docs/topics/models/versions.md)).
- **The prediction lifecycle as the remote job model**: `starting`, `processing`, `succeeded`, `failed`, `canceled`; `urls.get` and `urls.cancel`; webhooks filtered by event ([predictions](https://replicate.com/docs/topics/predictions/create-a-prediction.md)).
- **Signed, replay-resistant webhooks**: HMAC over `id.timestamp.body` with the id and timestamp in headers ([verify webhooks](https://replicate.com/docs/topics/webhooks/verify-webhook.md)). Clips Kitty's own job webhook signs the body but has no timestamp (signing `server/webhooks.py:55-60`, delivery `:84-104`).
- **The caller pays on their own account**: publishers host at no marginal cost and users pay the provider directly ([billing](https://replicate.com/docs/topics/billing.md)), which fits "no payment processing".

**Avoid.** Requiring Docker on the user's machine; "public" as the only trust signal; output URLs that expire after an hour without the local side fetching them at once.

**Decision.** A remote pipeline is a plugin whose process submits the job to its own service and polls or receives a callback; it uses the same job contract as a local one. The manifest carries the typed settings schema; results record the plugin version.

### Open WebUI: what should Clips Kitty borrow, and what security mistakes should it avoid? ([note](platform/research-notes/open-webui.md))

- **Borrow the bluntness.** The vendor says plugins "execute arbitrary Python code on your server. This is by design" ([plugins](https://docs.openwebui.com/features/extensibility/plugin)), "Listed does not mean vetted" ([community](https://docs.openwebui.com/ecosystem/community)) and "Treat plugin authors as administrators" ([under the hood](https://docs.openwebui.com/features/extensibility/plugin/development/under-the-hood)). Clips Kitty's install screen should say the equivalent in plain words.
- **Borrow typed settings (Valves and UserValves)**: a schema block rendered as a form, with secrets kept out of source and sharing that publishes code but not values ([valves](https://docs.openwebui.com/features/extensibility/plugin/development/valves)).
- **Borrow real kill switches**: one "plugins off" switch, an offline mode, automatic deactivation when a plugin fails to load.
- **Borrow the external tool-server shape**: tool servers "only see what you pass over HTTP", and the vendor sends "GPU access, large or conflicting dependencies, hard isolation" to an external OpenAPI or MCP tool server ([extensibility overview](https://docs.openwebui.com/features/extensibility)). This is H1 in production.
- **Borrow a written security policy** that says what is intended behaviour and what is out of scope ([security policy](https://docs.openwebui.com/security/security-policy)).

**Mistakes to avoid.**
1. `exec()` of database-stored plugin source inside the server. Disabling a plugin does not unload it, and module top-level code can monkey-patch the host ([under the hood](https://docs.openwebui.com/features/extensibility/plugin/development/under-the-hood)).
2. Runtime `pip install` of a plugin's requirements into the shared environment, on by default; the vendor now says "Strongly recommended: set `ENABLE_PIP_INSTALL_FRONTMATTER_REQUIREMENTS=False` in production" ([env reference](https://docs.openwebui.com/reference/env-configuration)).
3. Unvalidated metadata: a free-text version nothing compares, and a minimum-version check done only in the browser.
4. "Install from URL" that follows branches, not tags or commits.
5. A switch that is not a boundary: `ENABLE_PLUGINS=false` stops execution but "the create, update, delete and valves endpoints are not gated"; the vendor says to treat it "as a switch for whether plugins run, not as an authorization boundary" ([env reference](https://docs.openwebui.com/reference/env-configuration)).
6. A registry-to-app bridge over `window.postMessage` with no origin check, which let "any website ... steal a signed-in user's session token" ([GHSA-vpq8-f445-hcq7](https://github.com/open-webui/open-webui/security/advisories/GHSA-vpq8-f445-hcq7), published 2026-09-27); and a stored XSS that became remote code execution because the admin UI can write code ([GHSA-w7xj-8fx7-wfch / CVE-2025-64495](https://github.com/advisories/GHSA-w7xj-8fx7-wfch), 2025-11-07).
7. A code-execution feature beside weak default access: a campaign reported on 2026-03-18 compromised 45 of 98 instances found with authentication turned off ([Compare the Cloud](https://www.comparethecloud.net/news/open-source-ai-servers-hijacked-with-cryptominers-and-infostealers-for-over-a-year), press reporting Cybernews research).

**Decision.** Clips Kitty's engine has no authentication and only a Host-header check (`server/api.py:577-589`). Point 6 and 7 apply directly: **installing a plugin must never be possible through a bare local HTTP call**. Install, update and enable require a user action in the desktop app plus a per-session secret the web page cannot know; the engine refuses those routes without it.

### Stability Matrix: what should Clips Kitty borrow regarding model management? ([note](platform/research-notes/stability-matrix.md))

- **Let each consumer declare how it wants shared models**: Stability Matrix packages declare a recommended sharing method (symlink or junction, a config-file path entry, or none) ([shared folders](https://docs.lykos.ai/stability-matrix/advanced/shared-folders.html)). Prefer giving a plugin a path list over linking folders; on Windows use NTFS junctions, which need no symlink privilege.
- **Move-then-link with a hash-aware merge** when adopting an existing model folder, and "only remove links we created" ([note §8](platform/research-notes/stability-matrix.md)).
- **Typed category folders with a rename map** from day one (`SharedFolderType`, `LegacySharedFolderMapping`).
- **A portable data directory found by a marker file** (`Data/.sm-portable`) before the per-user default ([data directory](https://docs.lykos.ai/stability-matrix/getting-started/data-directory.html)).
- **Known-vulnerability fields per package** (advisory id, severity, affected versions, link) shown in the app ([note §7](platform/research-notes/stability-matrix.md)).
- **One virtual environment per package with interpreters shared** under one folder, provisioned by `uv` ([note §4](platform/research-notes/stability-matrix.md)).

**Avoid.** Compiling the catalogue into the app (39 C# classes, a pull request per package), downloading Hugging Face files at `resolve/main` with no commit pin, and accepting pickle formats with no warning ([note §12](platform/research-notes/stability-matrix.md)).

**Decision.** The model manager hands plugins resolved file paths (the config-path method) and never relocates the user's files; it keeps a typed category per model and advisory fields per plugin in the index.

### Pinokio: what should Clips Kitty borrow regarding community application distribution? ([note](platform/research-notes/pinokio.md))

- **A consent dialog that names the exact git remote** before anything runs ("This will execute the 3rd party script downloaded from <url>", `pinokiod/server/views/env_editor.ejs:488`). Clips Kitty's version names `publisher/name`, version, commit and repository.
- **Install at a commit**: the installer supports `git switch --detach <hash>` (`pinokiod/kernel/api/script/index.js:239-295`).
- **A freshness delay for dependency installs**: block packages younger than 72 hours, exact pins exempt, and say which commands it does not cover ([manual §2](https://desktop.pinokio.co/docs/README.md)).
- **Shared caches by environment variable** (`HF_HOME`, `TORCH_HOME`, `UV_CACHE_DIR`, `PIP_CACHE_DIR` under one home), and an opt-in deduplication tool rather than a forced central library.
- **Opt-in hardware "check-ins"**: users post what GPU and VRAM an app ran on, which answers "will it run on mine" without telemetry.
- **Zero-cost discovery**: the old "Latest" list was a GitHub topic search, kept separate from the curated list.

**Avoid.** Calling a folder convention "isolated by default" when every script runs in a full shell (`pinokiod/kernel/shell.js:862`); a "verified" track that runs through one admin's direct messages and requires transferring the repository to his organisation, where he may edit it ([Script Policy](https://github.com/pinokiocomputer/pinokio)); executable manifests (`pinokio.js` menus are async functions); no compatibility fields; model downloads with no hash or format policy (a featured script pulls pickle files Hugging Face flags as unsafe, [issue #880](https://github.com/pinokiocomputer/pinokio/issues/880), open since 2025-01-06).

**Decision.** Copy the named-remote consent dialog and commit pinning. Developers keep their repositories; the registry never takes ownership. The manifest is inert data that CI can check.

### Eklipse.gg: what should Clips Kitty learn about gaming-specific clipping and the gaming creator market? ([note](platform/research-notes/eklipse.md))

- **The demand is real and the market is paid and closed.** Eklipse auto-clips Twitch, Kick, YouTube and Facebook streams into vertical clips for $24.99 a month or $179.99 a year, with "no free clipping tier" since 2026-06-01, and publishes no API, SDK, plugin system or developer programme (help-centre search for API, SDK and webhook returned nothing; `/developers/` redirects home) ([is Eklipse free](https://eklipse.gg/help/is-eklipse-free/); [note §G](platform/research-notes/eklipse.md)).
- **Detection is three-tiered**: per-game models for popular titles (Valorant ACE, CLUTCH; Fortnite elimination tiers; Marvel Rivals kill-feed reading), five genre configurations (FPS, battle royale, MOBA, tactical shooter, strategy), and a generic audio and reaction fallback for everything else ([how Gameplay Intelligence picks moments](https://eklipse.gg/help/how-gameplay-intelligence-picks-moments/), 2026-05-26).
- **The game is picked from platform metadata**, one game per VOD, with a manual "Resubmit" when it guesses wrong; "wrong game" is its most documented failure ([note §E](platform/research-notes/eklipse.md)).
- **Every clip carries a reason**: a score, a content type, a platform fit and "Why This Clip". Clip length varies by moment type (5 to 40 s).
- **Typed event labels per game**, plus generic signals (high viewers, funny moments, a "clip it" voice command with a 180 s window).

**Avoid.** Opaque engine swaps (Eklipse replaced its detection layer on one date with no way to compare or pin); silent fallback to the generic detector; one game per VOD; feature claims that drift between pages ("1000+" and "3,000+" games).

**Decision.** Pipelines declare the event labels they can emit and the games they cover; the app routes game → genre → generic with a visible override and says in the result when the generic path ran; clips keep a reason. Clips Kitty should expect a few deep, community-maintained game pipelines, not thousands of shallow ones, because per-game detectors are costly to build and break when games patch (Overwolf keeps a per-game event health page for this reason: [clippers note §A](platform/research-notes/gaming-clippers.md)).

## 7.4 Cross-cutting lessons

### What makes an extension ecosystem successful

1. **A low floor.** The extension unit is one folder with one small manifest and one entry point: ComfyUI (a folder under `custom_nodes/`), Obsidian (`main.js`, `manifest.json`, `styles.css`), Home Assistant (`custom_components/<domain>/manifest.json`), Godot (`plugin.cfg` with six keys) ([ComfyUI](platform/research-notes/comfyui.md), [Obsidian](platform/research-notes/obsidian.md), [Home Assistant](platform/research-notes/home-assistant-hacs.md), [Godot](platform/research-notes/game-engines.md) notes). Nobody had to learn the host's internals to start.
2. **Developers publish where they already work.** Obsidian installs straight from the developer's GitHub release whose tag equals `manifest.version` ([submit your plugin](https://docs.obsidian.md/Plugins/Releasing/Submit+your+plugin)); HACS installs from the developer's release tag ([HACS include](https://hacs.xyz/docs/publish/include)); Zed pins the developer's repository as a submodule; Unity accepts a Git URL with `#tag` ([scoped registries](https://docs.unity3d.com/Manual/upm-scoped-use.html)). The developer keeps ownership.
3. **Discovery and install inside the app.** A1111's Extensions tab, Node-RED's Palette Manager, the HACS store inside Home Assistant, ComfyUI-Manager and VS Code's Extensions view all read an index and install without leaving the app ([A1111 and Node-RED](platform/research-notes/other-registries.md), [HACS](platform/research-notes/home-assistant-hacs.md), [ComfyUI](platform/research-notes/comfyui.md), [VS Code](platform/research-notes/vscode-openvsx.md) notes).
4. **Machine-readable compatibility.** VS Code `engines.vscode`, Obsidian `minAppVersion` plus `versions.json`, Blender `blender_version_min`/`max`, Node-RED `node-red.version`, Unity `unity`; Godot shows that keeping it only on the store form makes it uncheckable offline ([game engines note](platform/research-notes/game-engines.md)).
5. **Fast automated checks, humans for exceptions.** Obsidian reviews each version "within a few minutes" ([submit your plugin](https://docs.obsidian.md/Plugins/Releasing/Submit+your+plugin)) and keeps humans for popular, featured and flagged plugins ([future of plugins](https://obsidian.md/blog/future-of-plugins/)); A1111's `validate.py` and HACS's checks run on every pull request.
6. **Versioning discipline.** Immutable versions (ComfyUI registry, MCP registry, Obsidian releases, Replicate hashes), a way back (VS Code "Install Another Version", ComfyUI snapshots, HACS's last five releases) and a kill list (VS Code's block list, HACS's removed list, Blender's block list with a reason).
7. **Examples shipped with the extension.** ComfyUI packs ship `example_workflows/`; OBS and Raycast publish templates that build releases from a tag ([ComfyUI](platform/research-notes/comfyui.md), [OBS and Raycast](platform/research-notes/other-registries.md) notes).
8. **Free to publish.** A1111, HACS, Node-RED, Obsidian, Blender, Zed, ComfyUI's registry and Open VSX charge publishers nothing; the paid stores (Fab, Unity Asset Store, Overwolf) are the ones that can afford full human review.

### Mistakes to avoid

1. **Calling a convention or a declaration a boundary.** Pinokio's "isolated by default" is a folder convention; Blender's permissions are "not a security-oriented feature" ([Blender, 2024-05](https://code.blender.org/2024/05/extensions-platform-beta-release/)); Open WebUI's plugin switch is "not an authorization boundary".
2. **Mutable references.** Branch installs (A1111, InvokeAI's UI clone, Open WebUI's URL import), `skills-latest` (Kilo), `resolve/main` model downloads (Stability Matrix, Clips Kitty's own `scripts/fetch_asd_model.py`).
3. **Install-time code.** A1111's `install.py`, ComfyUI's `install.py` and `prestartup_script.py`, Unreal's `PreBuildSteps`, npm lifecycle scripts. Every ComfyUI incident used one of these hooks.
4. **One shared environment that plugins change.** ComfyUI needs overrides, blacklists and auto-fix lists to keep it working; Open WebUI's installs "race across workers and crash".
5. **Index automation that runs plugin code or holds publish secrets** (Open VSX, CVE-2025-6705).
6. **A browser-reachable install path** (Open WebUI GHSA-vpq8-f445-hcq7).
7. **Badges named for more than they mean** ("verified" = not flagged; "verified" = one admin).
8. **A human queue as the only gate** (Obsidian's 2,300; Zed and HACS measured in weeks to months).
9. **Changing the hosting model after launch.** Godot's new store needed a manual migration because the old Asset Library "doesn't actually host any of the assets it distributes" ([Godot, 2026-05-22](https://godotengine.org/article/introducing-the-godot-asset-store/)).
10. **Depending on one steward.** InvokeAI's curated community-node list has been frozen since its team moved to Adobe in 2025-10 ([note](platform/research-notes/invokeai.md)); ComfyUI-Manager moved into Comfy-Org in 2025-03; Kilo was acquired in 2026-07. A static index in a public repository can be forked if its steward leaves (inferred).

### Verdicts on the working hypotheses

| # | Hypothesis | Verdict | Evidence, and what it changes |
|---|---|---|---|
| H1 | Out-of-process plugins speaking the local API are the lowest-risk model; holds only if a separate process can reach the API. | **Confirmed, with two conditions.** | A separate process can reach the API: it listens on `127.0.0.1:8765` with no authentication and any local process can call it (`main.py:162-172`; `server/api.py:577-589`; the MCP server and OBS plugin already do, `server/mcp.py:16-20`). The render worker child is an existing out-of-process precedent (`remote_render/worker.py:82-87`). But process separation alone gives crash isolation and keeps plugin code out of the engine's memory; it does not limit what the plugin can do to the user's files or network ([security note, H1](platform/research-notes/security-third-party-code.md#hypotheses)). Conditions: wrap each plugin process in OS limits where they are actually applied (a Job Object for lifetime and memory), and give each plugin its own credential so the engine can tell plugins apart. Language choice and one shape for local, remote and hybrid both hold. |
| H2 | The smallest useful contract is "video in, scored and labelled time ranges out"; returning finished clips should stay possible. | **Confirmed, with an amendment.** | Detection, rendering and registration are already separate (`analysis/fusion.py:54-70`; `core/pipeline.py:1123`, `:1563`). Three independent event schemas agree on the shape: Overwolf's highlight payload (`events`, `raw_events[{type,time}]`, `start_time`, `duration`), NVIDIA's (`Id`, `Significance`, start and end deltas), Medal's (`eventId`, `eventName`, `duration`) ([clippers note](platform/research-notes/gaming-clippers.md)). Amendment: a range may have several source segments (OpusClip, Open Shorts `segments[]`), the score is optional (ClipsAI and FunClip return unscored ranges), and each range carries an event label and a reason. Finished files go through `_register_clip`, which already accepts files it did not render (`core/pipeline.py:685-754`). |
| H3 | A static JSON index built by CI from one metadata file per extension, submitted by pull request, pointing at a pinned tag and commit; no backend. | **Confirmed, with conditions.** | A1111, HACS, Zed, Kilo, ComfyUI's first index and Blender's static `index.json` spec all work this way at no running cost ([matrix](#71-extension-ecosystems-matrix)). Conditions: CI reads metadata and never runs plugin code or holds a publish secret (Open VSX CVE-2025-6705); entries pin a full commit, because tags move; the client can point at a mirror. The MCP registry's namespace verification (GitHub, DNS or HTTP proof) is the model for "this publisher owns this id" ([about](https://modelcontextprotocol.io/registry/about)); for a GitHub-only registry, the repository owner in the pinned URL is that proof. |
| H4 | Hand review does not scale; plan automated validation from the start. | **Confirmed.** | Obsidian's 2,300+ queue and unreviewed later versions until 2026-05-12; Zed and HACS review measured in weeks to months; Pinokio's one admin; Fab pays for review with a 12% cut ([Obsidian](platform/research-notes/obsidian.md), [Zed](platform/research-notes/zed.md), [HACS](platform/research-notes/home-assistant-hacs.md), [Pinokio](platform/research-notes/pinokio.md), [Fab](platform/research-notes/game-engines.md) notes). |
| H5 | A declared permission is not an enforced one; API-scoped permissions can be enforced at the API, the rest stay declared unless sandboxed. | **Confirmed, with a correction.** | VS Code, Obsidian, Open WebUI, Blender, Kilo and Pinokio all document full access; Zed is the only host-enforced model (Wasm). Correction for Clips Kitty: while the existing local API stays unauthenticated, a plugin process running as the user can skip its scoped credential and call the open API directly, or read the data folder. So a scope check on the plugin's own credential is enforced by the engine **for calls made with that credential**, which keeps honest plugins inside their contract and lets the app attribute actions, but it is **not a security boundary** against a hostile plugin until the plugin process is confined (AppContainer network and file isolation) or the whole API requires a credential. Labels must say exactly that. |
| H6 | Ban runtime installs, eval/exec and obfuscation; one shared environment invites conflicts; one per plugin costs disk; choose deliberately. | **Confirmed on both halves.** | ComfyUI's standards and its January 2025 timeline; Open WebUI's reversal; ComfyUI-Manager's four repair mechanisms; Pinokio's own statement that every app reinstalls "torch, accelerate, xformers" ([security note, H6](platform/research-notes/security-third-party-code.md#hypotheses)). Clips Kitty's frozen build has no pip, cannot run `-m`, and fixes its packages at build time (`requirements.txt:66-70`; `clips-studio.spec`). Choice: one environment per plugin, owned by the plugin, and the heavy runtimes (FFmpeg, rendering, captions, the job system) provided by the host over its API so plugins do not each re-install them. |
| H7 | Pin Hugging Face revisions by full commit; the model manager is an index over existing stores; check Windows without symlinks; prefer safetensors. | **Confirmed, with caveats.** | Full-commit pins work ([download guide](https://huggingface.co/docs/huggingface_hub/guides/download)); the cache shares unchanged files except on Windows without symlinks, where it duplicates per revision ([cache guide](https://huggingface.co/docs/huggingface_hub/guides/manage-cache)). Caveats: a pin does not survive the owner deleting or squashing history, so record a file hash too (as `scripts/fetch_voice_model.py` already does); loaders can execute code (CVE-2026-4372); pickle scanners have been bypassed. In the repo, only the two voice models are pinned by commit and SHA-256; YOLO, TalkNet, Whisper and Ollama models are not (`docs/platform/repo-map.md` §7.2). |
| H8 | Namespaced ids plus typed capabilities let several implementations of `highlight_detection` coexist. | **Confirmed.** | Namespacing is universal where it works (VS Code `publisher.name`, Hugging Face `owner/name`, MCP's verified namespaces, Unity's reverse-DNS names); flat namespaces cause collisions handled after the fact (ComfyUI's "Conflicted Nodes", Kilo's first-PR-wins). Typed capabilities with several implementations exist in OpenRouter (model → endpoints) and Replicate (schema per version). |
| H9 | Eklipse tunes per genre with no API; Overwolf is the nearest per-game precedent with gated approval and a 20–30% share; a free open per-game ecosystem fits between them. | **Confirmed, with two corrections.** | Eklipse tunes per genre *and* per game (dedicated models for popular titles), and has no API, SDK or plugin system ([Eklipse note](platform/research-notes/eklipse.md)). Overwolf's approval is gated by a proposal whitelist and QA; "20–30%" is its marketing wording, while its Developer Terms (updated 2025-10-09) set 15% of subscription revenue and 30% of ad revenue, and its separate Monetization Terms (updated 2025-11-23) reportedly require 6 or 12 months' notice before monetising an app elsewhere (not confirmed: taken from a summary of that page, not its quoted text) ([clippers note §A.12](platform/research-notes/gaming-clippers.md)). No product studied lets a third party add a game detector, so the gap is real. |
| H10 | Counts need telemetry; stars and last-updated can come from GitHub at build time; design counts as opt-in, build no telemetry. | **Confirmed, refined.** | A1111 refreshes stars and last commit daily from GitHub at index build; Node-RED shows npm downloads; Hugging Face counts downloads server-side ([notes](platform/research-notes/other-registries.md)). Refinement: GitHub release download counts are available without telemetry but measure downloads of release assets, not installs, so they must be labelled "release downloads"; all counts are gameable (bots inflated GlassWorm's counts, [Eclipse, 2025-10](https://blogs.eclipse.org/post/mikaël-barbero/open-vsx-security-update-october-2025)). |

## 7.5 Repository findings

Full detail with a file path for every claim: [`docs/platform/repo-map.md`](platform/repo-map.md) and its 12 area notes.

- **One engine, one API.** The engine is a FastAPI app on `127.0.0.1:8765` built by `create_app` (`server/api.py:572`) with 176 route decorators over 153 paths; optional features mount through `install(app, …)` (`server/api.py:629-706`). `API_VERSION = 1`, "bumped only when a supported endpoint changes shape" (`server/api.py:34`); `docs/API.md:127-142` already draws the supported/internal line. There is **no authentication**, only a Host-header check (`server/api.py:577-589`).
- **The pipeline is one function with flag predicates**, `process_video` (`core/pipeline.py:192`), stages communicating "only through dataclasses and files" (`ARCHITECTURE.md:1001`). Detection (`find_clips`), rendering (`_render_files`) and registration (`_register_clip`) are separate functions.
- **Gaming and Sports are not separate pipelines.** Each is a scoring profile passed to `find_clips` plus hooks the pipeline calls inside try/except at 17 sites (`docs/platform/repo-map.md` §5). ## 7.6 The 46 questions

Each answer gives the decision, the evidence, a confidence level and what would change it. "Designed, not built" marks answers the first release documents but does not implement (brief §4.7: build only the foundation). Repository paths are relative to the repo root; web sources were read 2026-10-06.

### Architecture

**1. What should a Clips Kitty plugin be?**
- **Answer.** A plugin is a Git repository (GitHub first) that contains one manifest file at its root, `clipskitty.yaml`, plus whatever code and assets it needs. The manifest names the plugin (`publisher/name`), its version, what kind of extension it is, the Clips Kitty and plugin-API versions it works with, the command the engine runs, its settings, the models it needs, and the access it declares. It is installed into the per-user data folder at a pinned commit and runs as its own process; the engine never imports it. The first release supports one kind, `pipeline`. Caption styles, publishers, sources, model providers and UI panels are designed as later kinds.
- **Evidence.** Every in-process model in the matrix gives plugins the host's access (§7.1, Security column); Open WebUI recommends external tool servers for "hard isolation" ([extensibility](https://docs.openwebui.com/features/extensibility)). The frozen build has no pip and cannot run `-m` (`requirements.txt:66-70`), so in-process plugins could use only the packages bundled with it, and MSIX installs are read-only (`core/paths.py:83-124`). One-file manifests: ComfyUI, Obsidian, HA, Zed, Blender ([ComfyUI](platform/research-notes/comfyui.md), [Obsidian](platform/research-notes/obsidian.md), [HA](platform/research-notes/home-assistant-hacs.md), [Zed](platform/research-notes/zed.md), [Blender](platform/research-notes/blender.md) notes).
- **Confidence.** High.
- **What would change it.** A need for plugins that change the desktop UI itself (they would need a renderer-side extension model, which Electron's sandboxed renderer and CSP make deliberate work: `ui/src/renderer/index.html:7-8`), or a Windows sandbox cheap enough to make in-process loading safe (none exists for Python).

**2. What should a pipeline be?**
- **Answer.** A pipeline is a plugin that implements a *capability*, in the first release `highlight_detection`: given a job (the source video's path and facts, optionally the transcript, and the user's settings for it) it returns **scored, labelled time ranges** (one or more source segments each, an optional score, an event label, a title or hook, a reason) or **finished clip files**. Clips Kitty does everything around it with its existing code: download, transcription, rendering, captions, the title card, registration, the library, publishing. The user picks a pipeline per job; with none picked, today's behaviour runs unchanged. Clips Kitty's own Shorts, Gaming and Sports modes stay in the app and are described as *official pipelines* in the same catalogue, without being moved or rewritten.
- **Evidence.** The pipeline already separates detection (`analysis/fusion.py:54-70`) from rendering (`core/pipeline.py:1123`) and registration (`core/pipeline.py:1563`); the registration funnel already accepts files it did not render (`core/pipeline.py:685-754`). The same output shape appears in Eklipse, OpusClip, Open Shorts, Overwolf, NVIDIA and Medal (§7.2; H2).
- **Confidence.** High.
- **What would change it.** A pipeline that needs to change how Clips Kitty frames or renders a clip (Gaming's layouts do this, `gaming/run.py:103,183`). That is designed as a later "render hint" field and a later `framing` kind, not built now.

**3. What should a model be?**
- **Answer.** A model is a **reference**, not a file Clips Kitty hosts: `{source, id, revision, files, sha256, format, licence, size}` where `source` is `huggingface`, `ollama`, `url` or `bundled`. A plugin lists the models it needs in its manifest; the model manager resolves each reference to local paths in the store that already holds it (the Hugging Face cache, Ollama's store, Clips Kitty's bundled `vendor/` folder) and hands the paths to the plugin.
- **Evidence.** Hugging Face pins by commit and caches per revision ([download guide](https://huggingface.co/docs/huggingface_hub/guides/download)); Ollama pins by digest ([API](https://docs.ollama.com/api.md)); Clips Kitty resolves each model in its own module today (`core/binaries.py`, `analysis/panns.py`, `video/asd.py`, `analysis/voice_turns.py`). Stability Matrix's config-path sharing never relocates files ([shared folders](https://docs.lykos.ai/stability-matrix/advanced/shared-folders.html)).
- **Confidence.** High for the shape; medium for how much of the existing resolvers to fold in during the first release.
- **What would change it.** A model source that is neither files nor a served model (for example a remote-only model id on a hosted API), which is handled as a remote pipeline, not as a model.

**4. What should a workflow be?**
- **Answer.** No new workflow unit in the first release. A "workflow" in Clips Kitty is a pipeline plus saved job options and a follow-up action, which already exist: job options (`JobIn`, `server/api.py:39-66`), the `then` action, automation watches with presets (`server/automation.py`) and streamer presets (`server/integrations.py:37-58`). A pipeline's settings join those presets. A graph editor of the ComfyUI kind is out of scope.
- **Evidence.** ComfyUI's and InvokeAI's workflows are graphs because image generation composes many small nodes ([notes](platform/research-notes/comfyui.md)); clipping has a fixed flow in which only detection varies (`core/pipeline.py:192-682`). Kilo, Open WebUI (filters chain per chat, no DAG), OpenRouter, Replicate and every gaming clipper have no workflow unit (§7.1, §7.2).
- **Confidence.** Medium.
- **What would change it.** Pipelines that need to chain (for example a game-event detector followed by a separate meme detector). Designed later as a pipeline that lists other capabilities it consumes.

**5. What should remain internal?**
- **Answer.** The routes `docs/API.md` already calls internal (assistant, feedback, branding, creator memory, caption editing, AI edits, AI keys and sign-in, credential `PUT`s, `PATCH /settings`, voices, translation editing); the SQLite schema and data-folder layout; every Python module (plugins never import Clips Kitty); the secrets store; build and release tooling; `third_party/talknet/`.
- **Evidence.** `docs/API.md:127-142`; `server/mcp.py:472-477` (keys deliberately not exposed); `PROJECTS.md` (schema "change without notice"); `docs/platform/repo-map.md` §13.
- **Confidence.** High.
- **What would change it.** A plugin kind that needs one of these (a publisher plugin would need a credential surface: designed later, through the existing secrets store and never by returning secrets).

**6. What should become public?**
- **Answer.** Three things, each with a version: (1) the **supported HTTP API** as it stands (`API_VERSION = 1`), documented as a reference with a stability label per route; (2) a new **plugin API** (version `1`): the job contract (`job.json` in, `result.json` out, progress lines), the manifest schema, and a small set of plugin endpoints on the engine; (3) a **minimal Python SDK** that reads a job, reports progress and writes results using only the standard library.
- **Evidence.** `server/api.py:34` and `docs/API.md:127-142` already define a supported surface; the remote-render protocol (`remote_render/protocol.py:15-33`) is the precedent for a versioned job contract handed to another process; OBS, MCP and `examples/drive_the_api.py` already depend on the HTTP API (`docs/platform/repo-map.md` §3.3).
- **Confidence.** High.
- **What would change it.** A decision to put the plugin endpoints behind authentication for every route (7.7, question 4).

### Existing API

**7. What parts of the existing API are reusable?**
- **Answer.** All of the supported surface, unchanged: health and preflight (a plugin checks `api_version` and blocking checks), jobs and queue, local import, library reads and media, captions and words, export, `/ws` events, webhooks, streamer integrations, automation and the publishing plan→execute pair. Internally, the platform reuses `install(app, …)` for its new routes, the job worker and queue, `core.progress.emit` → `/ws`, `core/cancel.py`, the job log, `_render_files`, `_register_clip` and `core/secrets.py`.
- **Evidence.** `docs/platform/repo-map.md` §13 "reused exactly as-is" and §14 (capability table with paths).
- **Confidence.** High.
- **What would change it.** Nothing expected; anything reused is used as it is.

**8. What parts should become stable interfaces?**
- **Answer.** The supported HTTP routes (already promised by `docs/API.md:127-142`), plus a written stability label on each: *stable* (changes only with an `API_VERSION` bump), *supported* (additive changes only), *internal* (may change). New stable interfaces: the plugin job contract, the manifest schema, the result schema, the progress-line format, the plugin endpoints, and the event `type` values a plugin can see. Contract tests pin the shapes of the routes the SDK uses.
- **Evidence.** `server/api.py:34` ("bumped only when a supported endpoint changes shape, never for additions"); the event `type` union and free-form `progress.stage` strings are de facto contracts the UI mirrors by hand (`server/jobs.py:37-46`; `ui/src/renderer/src/lib/jobProgress.ts:17-28`).
- **Confidence.** High.
- **What would change it.** A route the SDK needs that is currently internal (it would be promoted with a CHANGELOG note, not used silently).

**9. What should not be exposed?**
- **Answer.** To plugins: any route not in their declared scopes; secrets (no route returns them today, `server/ai_api.py:9-12`, and none will); the settings writer; other plugins' data; the install and enable routes of the plugin manager itself. On the open loopback API: plugin install, update and enable must not be callable without the desktop app's per-session secret, because the API has no authentication and a web page or a stray script could otherwise install code (the Open WebUI bridge advisory, GHSA-vpq8-f445-hcq7, is the precedent). The secret does not stop software already running as the user, which can read it (see the table at the top).
- **Evidence.** `server/api.py:577-589` (no auth, Host check only); `SECURITY.md`; [GHSA-vpq8-f445-hcq7](https://github.com/open-webui/open-webui/security/advisories/GHSA-vpq8-f445-hcq7).
- **Confidence.** High.
- **What would change it.** Authentication on the whole local API (7.7, question 4).

**10. How can external developers access pipelines without importing internal code?**
- **Answer.** Two ways, both over plain data. (a) **As a client**, any process can already drive Clips Kitty's own pipelines over HTTP (`POST /jobs`, `/ws`, `GET /videos/{id}/clips`), now with documented stability labels. (b) **As a pipeline**, a plugin receives a `job.json` and answers with a `result.json` and progress lines; it may call the HTTP API with its own scoped credential for anything more. The SDK wraps both using the standard library only, and the example pipeline's tests prove it imports nothing from Clips Kitty.
- **Evidence.** `examples/drive_the_api.py`; `server/mcp.py:16-20` ("No second engine. Every tool asks the running engine over 127.0.0.1:8765"); `remote_render/worker.py:82-87` (job folder handed to a child process).
- **Confidence.** High.
- **What would change it.** A pipeline that needs Clips Kitty's in-process models (YOLO, OCR, PANNs) as functions; designed later as host endpoints ("run OCR on these frames"), not as imports.

### Distribution

**11. Should plugins primarily be GitHub repositories?**
- **Answer.** Yes. A plugin is installed from a GitHub repository at a tag and a full commit; the developer keeps the repository, issues, releases and licence. The source field is a plain Git URL so other hosts can be added later, but the first release accepts only `https://github.com/<owner>/<repo>`.
- **Evidence.** Obsidian, HACS, Zed, A1111, Kilo, Unity Git URLs and Pinokio all install from the developer's own Git repository (§7.4 success factor 2). The owner's fixed decision: developers never fork Clips Kitty and keep ownership (brief §3, §4.8). `ui/src/main/index.ts:487-570` (`EXTERNAL_ALLOWED`) already treats GitHub specially.
- **Confidence.** High.
- **What would change it.** Developers who need binaries larger than GitHub release assets allow (Clips Kitty itself moved its installer payload to Hugging Face for that reason, `docs/RELEASING.md`). Large files belong in model references, not in plugin code.

**12. Should the registry be centralized, decentralized, or hybrid?**
- **Answer.** **Hybrid.** One official static index, built by CI from one metadata file per plugin in a public Git repository and reviewed by pull request; plus installation from any GitHub URL, labelled "not listed"; plus a setting to add other index URLs (mirrors or community indexes), Jellyfin-style. The app never needs a server to install.
- **Evidence.** Static indexes cost nothing (A1111, HACS, ComfyUI's first index, Blender's static `index.json`); Jellyfin repositories are added by URL ([plugins](https://jellyfin.org/docs/general/server/plugins/)); Kilo's mirror override; Pinokio's dependence on a hosted iframe is what to avoid ([note](platform/research-notes/pinokio.md)).
- **Confidence.** High.
- **What would change it.** A need for server-side features (accounts, ratings, download counting), which the fixed decisions rule out.

**13. How should updates work?**
- **Answer.** The app refreshes the cached index when the user opens the Marketplace (no background polling), shows "update available" with the new version's changelog link and any change in declared access, and installs only when the user clicks. The new version installs beside the old one and becomes active only after it installs cleanly; the old one stays for rollback. No automatic updates by default; an opt-in per plugin is designed for later.
- **Evidence.** VS Code per-extension auto-update and "Install Another Version"; Blender's open TODO for warning when an upgrade adds permissions; Kilo's update-by-removal to avoid; Clips Kitty's own updater never installs without a click (`ui/src/main/updater.ts`).
- **Confidence.** High.
- **What would change it.** A security fix that must reach users quickly: handled by the block list (which disables a bad version) rather than by forced updates.

**14. How should version pinning work?**
- **Answer.** Plugins use SemVer. Each index entry maps a version to a tag **and** a 40-character commit; the installer fetches that commit, checks that it matches, and checks that the manifest's version equals the entry's. The installed plugin records its commit. Jobs and clips record `publisher/name@version`. A user can pin a plugin so it is never offered updates.
- **Evidence.** Tags can be moved ([security note, closing table](platform/research-notes/security-third-party-code.md#closing-table)); Zed pins a submodule commit; the MCP registry rejects version ranges; Obsidian requires the release tag to equal `manifest.version` ([Zed](platform/research-notes/zed.md), [MCP registry](platform/research-notes/mcp-registry.md), [Obsidian](platform/research-notes/obsidian.md) notes).
- **Confidence.** High.
- **What would change it.** GitHub immutable releases becoming universal (its general availability was reported on 2025-10-28; not confirmed beyond the announcement title), which would make the tag alone enough.

**15. How should rollbacks work?**
- **Answer.** Keep the previously active version's folder after an update; "Roll back" makes it active again. Keep a small history of the plugin set (ComfyUI-style snapshot: app version and every plugin's version and commit) written before each change. Versions are never deleted from the index; a bad version is marked deprecated or blocked.
- **Evidence.** ComfyUI snapshots; HACS's last five releases; VS Code's "Install Another Version"; Replicate's rule that used versions cannot be deleted ([ComfyUI](platform/research-notes/comfyui.md), [HACS](platform/research-notes/home-assistant-hacs.md), [VS Code](platform/research-notes/vscode-openvsx.md), [Replicate](platform/research-notes/replicate.md) notes).
- **Confidence.** High.
- **What would change it.** Disk pressure from keeping old versions of heavy plugins (Colin's PC is tight on disk per project memory); the number kept can be one.

### Models

**16. How should Hugging Face models be referenced?**
- **Answer.** `source: huggingface`, `id: owner/name`, `revision: <40-hex commit>`, `files: [...]` (exact names or globs), optional `sha256` per file, plus `format` and `licence` copied from the model card for display. Never `main`, a tag or a short hash. Placeholder for docs: `example-org/example-model`.
- **Evidence.** [Download guide](https://huggingface.co/docs/huggingface_hub/guides/download) (`revision`); [Hub API](https://huggingface.co/docs/hub/api) (`sha`, `siblings`, `license`); Clips Kitty's own `scripts/fetch_voice_model.py` already pins repo, commit and SHA-256.
- **Confidence.** High.
- **What would change it.** Nothing expected.

**17. How should revisions be pinned?**
- **Answer.** By full commit, resolved once by the developer when publishing (the index CI checks that the commit exists and is 40 hex characters), and verified after download by the file's SHA-256 (the Hub's LFS etag is the SHA-256 of the file). A model whose commit disappears (history squashed or repo deleted) fails with a clear message rather than falling back to `main`.
- **Evidence.** Owners can delete tags and squash history ([note §5](platform/research-notes/hugging-face.md)); the cache's `blobs/` are named by etag, SHA-256 for LFS files ([cache guide](https://huggingface.co/docs/huggingface_hub/guides/manage-cache)).
- **Confidence.** High.
- **What would change it.** Nothing expected.

**18. How should duplicate model downloads be avoided?**
- **Answer.** By not owning a store. Hugging Face models go into one Hugging Face cache shared by every plugin (the library deduplicates unchanged files between revisions); Ollama models stay in Ollama's store; bundled models stay in `vendor/`. The model manager keeps an index keyed by source, id, revision and file hash so a second plugin asking for the same model gets the same paths. On Windows without symlink permission the cache duplicates files across revisions of the same model: the app detects this once and tells the user (enable Developer Mode, or accept the extra disk use) instead of hiding it. Plugins never copy models into their own folders.
- **Evidence.** [Cache guide](https://huggingface.co/docs/huggingface_hub/guides/manage-cache) (sharing and the Windows limitation); Pinokio's shared `HF_HOME` ([note](platform/research-notes/pinokio.md)); Stability Matrix's per-package path config ([shared folders](https://docs.lykos.ai/stability-matrix/advanced/shared-folders.html)).
- **Confidence.** Medium: the Windows behaviour is documented, not tested on Colin's PC.
- **What would change it.** A test on Windows showing the library's behaviour differs from its documentation.

**19. How should licences be surfaced?**
- **Answer.** Before any download, the install screen lists each model with its licence (from the model card's `license` field; for `other`, the `license_name` and link), its size, whether it is gated (with a link to accept terms on Hugging Face in the browser) and its format. The plugin's own licence comes from its repository and is required for listing. Clips Kitty never redistributes a model; it downloads from the original source.
- **Evidence.** [Licenses](https://huggingface.co/docs/hub/repositories-licenses); [gated models](https://huggingface.co/docs/hub/models-gated); Ollama exposes the licence via `/api/show` ([API](https://docs.ollama.com/api.md)); Kilo and HACS require a licence file ([Kilo](platform/research-notes/kilo-code.md), [HACS](platform/research-notes/home-assistant-hacs.md) notes); brief §4.15.
- **Confidence.** High.
- **What would change it.** Nothing expected.

**20. Can Ollama models fit the same model abstraction?**
- **Answer.** Yes, with one difference. `source: ollama`, `id: name:tag`, `revision: <digest>`; the store is Ollama's; licence and capabilities come from `/api/show`. The difference is that an Ollama model is *served*, not handed over as files: a plugin uses it by calling Ollama's API (or, later, a Clips Kitty LLM endpoint), and the model manager's job is to make sure it is pulled and to report the host. Clips Kitty already pulls, lists and deletes Ollama models (`server/api.py:2811-2920`).
- **Evidence.** [Ollama API](https://docs.ollama.com/api.md) (`/api/tags`, `/api/show`, digests); [Hugging Face on Ollama](https://huggingface.co/docs/hub/en/ollama) (`hf.co/owner/repo:quant`) shows the two sources already meet ([note](platform/research-notes/ollama.md)).
- **Confidence.** High.
- **What would change it.** Nothing expected; the existing Gemma path is not touched.

### Execution

**21. How should local pipelines run?**
- **Answer.** Inside the existing job, as one more step of the existing pipeline, never as a second engine. When a job names a pipeline plugin, `process_video` runs download and transcription as today, then, at the detection step, the engine writes a job folder (`job.json` with the source path, duration, title, the transcript path if the plugin declared it, and the user's settings) and starts the plugin's declared command as a child process with that folder. The plugin writes progress lines to standard output and a `result.json`; the engine enforces a timeout and the existing cancel, validates the result against the schema, turns ranges into `ClipCandidate`s, and renders and registers them with the existing `_render_files` and `_register_clip`. With no plugin named, nothing changes.
- **Evidence.** The render-worker child is the precedent (`remote_render/worker.py:82-87`, job folder plus allow-listed config slice, `remote_render/protocol.py:15-33`); `core/cancel.py:99` already runs and cancels subprocesses; the 17 adapter hook sites (`docs/platform/repo-map.md` §5.2) show where a detection step can be swapped without touching other branches.
- **Confidence.** High.
- **What would change it.** Plugins that need to stream results while the video is still downloading (live streams), designed later.

**22. How should remote pipelines run?**
- **Answer.** Through the same contract. A remote pipeline is a plugin whose process sends work to its developer's service and returns the same `result.json`; it polls or receives a callback from the service, never on the engine's open port. Its manifest must declare `sends_media` (what leaves the machine: `video`, `audio`, `frames`, `transcript`) and the hosts it contacts; the app shows "⚠ This pipeline sends video data to Example Cloud" on the listing, at install and on the job before it starts, and nothing is uploaded without that. Payment and accounts are between the user and the developer's service.
- **Evidence.** Replicate's prediction lifecycle and signed webhooks ([predictions](https://replicate.com/docs/topics/predictions/create-a-prediction.md)); OpusClip's submit-poll-callback API ([overview](https://help.opus.pro/api-reference/overview)); Open Shorts refuses non-public webhook URLs, so a local adapter must poll ([note §B](platform/research-notes/clipping-pipelines.md)); brief §4.18.
- **Confidence.** High.
- **What would change it.** A "no local code" remote kind where the engine itself calls a developer URL (simpler for developers, but it puts uploads inside the engine). Designed, not built.

**23. How should hybrid pipelines work?**
- **Answer.** As a local plugin that does part of the work itself (for example extracting audio, frames or the kill-feed region) and sends only that to its service, declaring exactly what it sends. The listing and job warning name the derived data ("sends audio and sampled frames to Example Cloud") rather than "video". The engine does not distinguish hybrid from remote beyond what the manifest declares.
- **Evidence.** Open Shorts can run its moment picker against a local Ollama while frame stages need Gemini ([note](platform/research-notes/clipping-pipelines.md)); Clips Kitty's own optional cloud LLM and cloud transcription keys work the same way (`llm/providers/catalog.py`; `transcription/cloud.py:56`).
- **Confidence.** Medium: the declaration is only as honest as the developer, which is why it is labelled "declared".
- **What would change it.** Network confinement of plugin processes (AppContainer), which would let the app enforce the declared hosts.

**24. How should jobs be tracked?**
- **Answer.** In the existing jobs table and worker, with no new queue. The job payload records the pipeline id and version; each clip it produces records `publisher/name@version` in its stored metadata; the plugin's standard error goes into the existing per-job log. A plugin that fails or times out fails the job with its message, unless the user asked to fall back to the built-in detector, in which case the result says so.
- **Evidence.** `core/state.py:62-70` (jobs), `server/jobs.py:49-340` (one worker), `server/jobs.py:150` (job log), `core/pipeline.py:1472-1480` (per-clip persisted options). Eklipse's silent generic fallback is the thing to avoid ([note](platform/research-notes/eklipse.md)).
- **Confidence.** High.
- **What would change it.** Concurrent plugin runs (the single worker is a deliberate limit today, `server/jobs.py`); designed later.

**25. How should progress be reported?**
- **Answer.** The plugin prints JSON lines to standard output (`{"type": "progress", "fraction": 0.4, "message": "Reading kill feed"}`); the engine forwards them through the existing `core.progress.emit` as a new `plugin` stage, which reaches the UI over `/ws` like every other stage. Plugins can also log plain lines, which go to the job log. The SDK has one function for each.
- **Evidence.** `core/progress.py:18-39`, `server/events.py`, `server/jobs.py:37-46` (`_STAGES`, mirrored in `ui/src/renderer/src/lib/jobProgress.ts:17-28`); Gaming and Sports emit no progress today, only `print()` (`docs/platform/repo-map.md` §4.4).
- **Confidence.** High.
- **What would change it.** Nothing expected.

### Security

**26. How much access should plugins have?**
- **Answer.** By design: the job folder (read the inputs, write the result), the model paths the manager hands over, and the plugin endpoints its scopes allow. **In fact**: a plugin process runs with the signed-in user's rights and can read and write anything the user can, reach the network, and call the open local API. The app says so on the install screen, in plain words. What the engine checks is listed under question 28 with its label.
- **Evidence.** [Security note, H1 and H5](platform/research-notes/security-third-party-code.md#hypotheses); `server/api.py:577-589`.
- **Confidence.** High.
- **What would change it.** OS confinement of plugin processes (question 27).

**27. Should plugins run isolated?**
- **Answer.** Yes, as separate processes, always. On Windows, each plugin process should also be placed in a Job Object (kill when Clips Kitty exits, memory and process-count limits), which costs the user nothing; this is designed now and built only if it can be tested, and the app will call it enforced only once it is. AppContainer confinement (files, network, devices) is the real boundary and is designed for later, because every model and data path the plugin needs must be granted explicitly. WebAssembly is the right isolation for logic-only plugins (scoring over data the host supplies) and is designed for later. Windows Sandbox, WSL and Docker need Pro editions or extra installs and are not plugin hosts.
- **Evidence.** [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects); [AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation) ("it can be complicated" for unpackaged apps: [legacy apps](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-for-legacy-applications-)); [Zed capabilities](https://zed.dev/docs/extensions/capabilities.html); [Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/) (not on Home edition).
- **Confidence.** High for process separation; medium for the Job Object timing.
- **What would change it.** Win32 app isolation leaving preview and supporting per-child profiles (not confirmed today, [overview](https://learn.microsoft.com/en-us/windows/win32/secauthz/app-isolation-overview)).

**28. Which permissions are necessary?**
- **Answer.** Each one is shown with its label. **Enforced by the engine** means the engine checks it and refuses otherwise; **declared** means the developer states it and nothing stops the plugin doing otherwise.

| Permission | Meaning | Label |
|---|---|---|
| `video.read` | the engine puts the source video's path in the job | enforced for the hand-over (no path without it); the process could still read files itself: declared beyond that |
| `transcript.read` | the engine writes the transcript into the job folder | enforced for the hand-over; declared beyond that |
| `clips.write` | the plugin may return finished files, which the engine copies into the library | enforced (the engine ignores returned files without it) |
| `models` | the model manager fetches only the models listed in the manifest | enforced for downloads the manager makes; a plugin can still download on its own: declared beyond that |
| `network` (hosts) | the hosts the plugin contacts | declared |
| `sends_media` | what data leaves the machine | declared, and shown as a warning |
| `gpu` | uses the GPU | declared (a requirement, not a permission) |
| `filesystem` | reads or writes outside its folder and the job folder | declared |
| plugin API scopes (`jobs.read`, `library.read`, …) | which plugin endpoints its credential may call | enforced by the engine for calls made with that credential; **not a security boundary** while the rest of the local API stays open |

- **Evidence.** Brief §4.19; [security note, H5](platform/research-notes/security-third-party-code.md#hypotheses); Blender shows permission reasons to users while stating they are "not a security-oriented feature" ([Blender, 2024-05](https://code.blender.org/2024/05/extensions-platform-beta-release/)).
- **Confidence.** High.
- **What would change it.** Confinement (question 27) would move `network` and `filesystem` to enforced; authentication on all routes would make the scopes a boundary.

**29. How should community plugins be trusted?**
- **Answer.** Never automatically. Trust is built from facts the user can check: the tier (Official, Listed, Installed from a link), the automated checks the index ran and their results, the publisher (GitHub owner) and repository, the exact commit, the licence, the declared access and data use, the last update, and the block list. The install dialog names publisher, repository, version and commit before anything is written, and says that the plugin will run with the user's rights. Plugins on the block list do not run, and the app says why.
- **Evidence.** Pinokio's named-remote dialog; VS Code's publisher-trust dialog (1.97) and block list ([runtime security](https://code.visualstudio.com/docs/configure/extensions/extension-runtime-security)); ComfyUI's startup block list; brief §4.16, §4.17.
- **Confidence.** High.
- **What would change it.** Nothing expected.

**30. What does "Verified" mean?**
- **Answer.** Nothing, yet: the first release has no "Verified" label. "Listed" means the index's automated checks passed and nothing more, and the UI says "not reviewed by a person". If Colin later sets up a real review (a named person checks a specific commit against a written checklist), the label would be "Reviewed" and would apply to that commit only. A label saying a plugin is safe would need a security audit, which no free registry studied performs.
- **Evidence.** ComfyUI's check icon means "not flagged"; Pinokio's "verified" means one admin; VS Code's "verified publisher" means domain ownership plus six months; Hugging Face's "Verified" commit means a GPG signature ([ComfyUI](platform/research-notes/comfyui.md), [Pinokio](platform/research-notes/pinokio.md), [VS Code](platform/research-notes/vscode-openvsx.md), [Hugging Face](platform/research-notes/hugging-face.md) notes); brief §4.19.
- **Confidence.** High.
- **What would change it.** A documented review process with someone to run it (7.7, question 5).

### Marketplace

**31. How should users discover niche pipelines?**
- **Answer.** A Marketplace page in the app that reads the cached index through the engine (the renderer can only talk to `127.0.0.1:8765`), with search, a category list (Gaming, Sports, Creators, Captions, Utilities), game and sport tags, the capability each implements, and "works with your setup" from preflight. Designed for later: suggesting a pipeline from the video's own metadata, since `DownloadedVideo.games` already carries the platform's game list (`core/models.py:11-25`), and a "requested games" list (Eklipse takes game requests in Discord).
- **Evidence.** `ui/src/renderer/index.html:7-8` (CSP); the Models page as the catalogue precedent (`ui/src/renderer/src/pages/Models.tsx:125-250`); Eklipse routes by platform category ([note §E](platform/research-notes/eklipse.md)); Overwolf's per-game event pages ([clippers note §A](platform/research-notes/gaming-clippers.md)).
- **Confidence.** High.
- **What would change it.** An index large enough that client-side search is slow (thousands of entries; A1111's and Node-RED's single-file indexes show this is far off).

**32. What categories/tags should exist?**
- **Answer.** A closed list of top-level categories checked by CI: `gaming`, `sports`, `creators`, `captions`, `utilities`. Tags are lower-case, at most 10 per plugin, and checked against a vocabulary that grows by pull request; game and sport tags use slugs (`game:marvel-rivals`, `sport:basketball`). Capabilities are separate from tags (`highlight_detection`).
- **Evidence.** A1111's `validate.py` checks tags against a vocabulary; Kilo uses a closed category set; HA's integration quality scale ([notes](platform/research-notes/other-registries.md)); brief §3's taxonomy (Gaming, Sports, Creators).
- **Confidence.** Medium: the exact list is a product choice.
- **What would change it.** Colin's preference for the list.

**33. How should quality be communicated?**
- **Answer.** With facts, each labelled for what it is: tier; the automated checks and their results; "compatible with your Clips Kitty"; requirements compared with this PC (GPU, VRAM, disk); the events the pipeline says it detects; the developer's example clips; last update and GitHub stars "at index build time"; known advisories. No score that blends these into one number.
- **Evidence.** Node-RED's scorecard is advisory, "not gatekeepers" ([scorecard](https://nodered.org/blog/2022/01/31/introducing-scorecard)); OpenRouter separates measured from declared ([note](platform/research-notes/openrouter.md)); Obsidian's scorecards ([community directory](https://docs.obsidian.md/Community+directory/Scorecards)).
- **Confidence.** High.
- **What would change it.** Nothing expected.

**34. Should ratings/stars exist?**
- **Answer.** No in-app ratings: they need accounts and a server, and they can be gamed. Show the repository's GitHub stars, labelled as GitHub stars and captured when the index was built.
- **Evidence.** Brief §4.20 (no social network, no SaaS backend); bot-inflated counts in GlassWorm ([Eclipse, 2025-10](https://blogs.eclipse.org/post/mikaël-barbero/open-vsx-security-update-october-2025)); A1111 shows stars from GitHub ([index](https://github.com/AUTOMATIC1111/stable-diffusion-webui-extensions)).
- **Confidence.** High.
- **What would change it.** Nothing expected.

**35. How should install/usage counts work?**
- **Answer.** No telemetry. The index build can record GitHub release download counts where a plugin ships release assets, labelled "release downloads" (not installs). Opt-in usage counts are designed for later only if Colin wants them.
- **Evidence.** H10 (§7.4); Pinokio's opt-in check-ins; Hugging Face counts on its own servers ([download stats](https://huggingface.co/docs/hub/models-download-stats)).
- **Confidence.** High.
- **What would change it.** Colin choosing opt-in telemetry (7.7).

**36. How should examples and outputs be shown?**
- **Answer.** The manifest lists `examples`: links to sample clips or images hosted by the developer (repository files or release assets) with a caption. The Marketplace shows them as links, and images fetched through the engine from allowed hosts. Clips Kitty hosts nothing.
- **Evidence.** ComfyUI's `example_workflows/`; Replicate requires an example run before listing ([publish a model](https://replicate.com/docs/topics/models/publish-a-model.md)); `EXTERNAL_ALLOWED` (`ui/src/main/index.ts:487-570`).
- **Confidence.** Medium: the image-proxy detail is a UI choice.
- **What would change it.** Nothing expected.

### Developer experience

**37. What is the minimum SDK needed?**
- **Answer.** (1) The manifest schema and a validator a developer can run locally (the same checks the index runs). (2) The job contract: `job.json` in, `result.json` out, progress lines, exit codes. (3) A small Python module using only the standard library: `read_job()`, `progress()`, `log()`, `write_result(ranges | clips)`, and a client for the plugin endpoints. (4) One worked example pipeline with a test. Nothing else for the first release.
- **Evidence.** ComfyUI's low floor and the cost of its four hooks; `comfy node validate` and Kilo's validators run before upload ([ComfyUI](platform/research-notes/comfyui.md), [Kilo](platform/research-notes/kilo-code.md) notes); brief §10 phases 3–5.
- **Confidence.** High.
- **What would change it.** Developers asking for helpers for common work (frame sampling, OCR); those come as host endpoints later.

**38. How easy is it to create a pipeline?**
- **Answer.** The target is: a manifest of about 20 lines plus one script that reads the job and writes ranges, testable without Clips Kitty running, in under an hour for someone who already has a detector. The example pipeline in this branch is the measure, and its end-to-end test runs it against a tiny generated video.
- **Evidence.** Inferred from the contract in questions 21 and 37; tested by the example pipeline (Phase 5).
- **Confidence.** Medium until a developer outside the project tries it.
- **What would change it.** The first outside developer's experience.

**39. Can developers use Python?**
- **Answer.** Yes, as the first-class language. The plugin brings its own Python environment or executable; Clips Kitty does not lend its own (the frozen engine has no pip). The SDK is a single standard-library module the plugin can vendor or install. Installing a plugin's dependencies from a hash-pinned lockfile into a per-plugin environment is designed, not built, in the first release.
- **Evidence.** `requirements.txt:66-70` (frozen build); ComfyUI and Open WebUI's shared-environment problems (H6).
- **Confidence.** High.
- **What would change it.** Nothing expected.

**40. Can developers use TypeScript/JavaScript?**
- **Answer.** Yes for pipelines, because the contract is JSON files, standard output and HTTP: any language that can read a file and print a line works. There is no official TypeScript SDK in the first release. Plugins that extend the desktop UI are not supported.
- **Evidence.** The contract design (question 21); the MCP server already speaks to the engine with the standard library only (`server/mcp.py:16-20`).
- **Confidence.** High.
- **What would change it.** Demand for a TypeScript helper, which is small to add.

**41. Can they create a remote-only pipeline?**
- **Answer.** Yes, as a thin local adapter (a short script) that forwards to their service, with `sends_media` declared and shown to the user. A no-code remote kind (the manifest gives a URL and the engine calls it) is designed, not built.
- **Evidence.** Question 22; Replicate and OpusClip's remote APIs ([Replicate](platform/research-notes/replicate.md), [OpusClip](platform/research-notes/clipping-pipelines.md) notes).
- **Confidence.** High.
- **What would change it.** Nothing expected.

**42. How much of Clips Kitty should they need to understand?**
- **Answer.** None of its internals. A developer needs the manifest, the job contract, the result schema and, if they want extras, the documented HTTP API. They never read `core/pipeline.py`. Clips Kitty's own Gaming and Sports modes stay internal; the docs explain what they do so developers know what the generic fallback is.
- **Evidence.** Brief §3 ("They do not build a complete video editor…"); the repository's own rule that stages talk only through dataclasses and files (`ARCHITECTURE.md:1001`).
- **Confidence.** High.
- **What would change it.** Nothing expected.

### Economics

**43. How do we keep the Marketplace free?**
- **Answer.** Run nothing. The index is a public Git repository; validation and the index build run on GitHub Actions; the app downloads one JSON file from GitHub; plugin code stays in developers' repositories and models at their sources. The remaining cost is maintainer time to merge pull requests, which automated checks keep small.
- **Evidence.** A1111, HACS and ComfyUI's first index ran this way at no running cost; Open VSX shows a free registry run by a non-profit still has incidents to manage ([A1111](platform/research-notes/other-registries.md), [HACS](platform/research-notes/home-assistant-hacs.md), [ComfyUI](platform/research-notes/comfyui.md), [Open VSX](platform/research-notes/vscode-openvsx.md) notes); GitHub Actions' free minutes for public repositories were not checked against GitHub's current billing page tonight (not confirmed).
- **Confidence.** High for the design; medium for the Actions pricing detail.
- **What would change it.** GitHub changing its terms for public repositories; the index can then be built by any static host because it is one JSON file.

**44. How do developers link to paid services?**
- **Answer.** The manifest carries `funding` links (GitHub Sponsors, Patreon, a website) and, for plugins that need a paid account, a `service` block (name, website, pricing page) with a label: *Free*, *Optional paid service*, or *Paid service required*. The listing shows the label and the links; links open in the browser through the existing allow-list.
- **Evidence.** Obsidian's Free, Optional payments and Paid labels and `fundingUrl` ([note](platform/research-notes/obsidian.md)); VS Code's `sponsor.url` ([manifest](https://code.visualstudio.com/api/references/extension-manifest)); brief §4.11.
- **Confidence.** High.
- **What would change it.** Nothing expected.

**45. How do we avoid processing their payments?**
- **Answer.** By having no payment fields, checkout, keys or accounts anywhere: only outbound links. A plugin that needs a licence key or an API key asks for it in its own settings (stored by Clips Kitty's existing secrets store, never sent anywhere by Clips Kitty).
- **Evidence.** Brief §4.11; `core/secrets.py:97-159`; Replicate and OpenRouter bill the user's own account ([Replicate](platform/research-notes/replicate.md), [OpenRouter](platform/research-notes/openrouter.md) notes).
- **Confidence.** High.
- **What would change it.** Nothing; this is a fixed decision.

**46. How can Clips Kitty benefit from ecosystem growth without taking developer revenue?**
- **Answer.** Every useful pipeline makes Clips Kitty more useful to the people who need it, which brings users, bug reports and contributors to the app; plugins reuse the app's rendering, captions, library and publishing, so the app's quality compounds; the registry shows where demand is (which games have pipelines and which are requested); and Clips Kitty can show its own sponsor link like any other project. It never takes a cut, charges a fee or controls a developer's listing beyond the published checks.
- **Evidence.** Brief §3 ("Every useful pipeline makes Clips Kitty more valuable"), §4.9–4.11; the paid stores take 12% (Fab), 15–30% (Overwolf) ([notes](platform/research-notes/game-engines.md), [clippers](platform/research-notes/gaming-clippers.md)).
- **Confidence.** High.
- **What would change it.** Nothing; this is a fixed decision.

## 7.7 Open questions for the owner

Each has the default this branch uses until Colin decides.

1. **Should plugins run in the Microsoft Store build?** Store builds are detected already (`ui/src/main/distribution.ts`). Running code downloaded after install may conflict with Store policy; the policy text was not checked tonight (not confirmed). *Default:* the plugin manager works in every build; hiding it in Store builds is a one-line switch if the policy requires it.
2. **Where should the registry live?** A separate public repository (for example `<owner>/clips-kitty-registry`, a placeholder) keeps registry pull requests out of the app's history and can have its own maintainers. The brief forbids creating repositories tonight. *Default:* a `registry/` folder in this repository with the same layout, ready to move.
3. **Which licence should the SDK and the example pipeline carry?** Clips Kitty is AGPL-3.0. Plugins talk to it over files and HTTP and import nothing from it, but the SDK module is meant to be copied into plugins, and a permissive licence (MIT or Apache-2.0) would remove any doubt for plugin authors. This is a legal choice. *Default:* the SDK stays under the repository's AGPL-3.0 with a note in its README that the licence choice is pending.
4. **Should the local API require a credential?** Today any local process can call every route. Requiring a token on all routes would make plugin scopes a real boundary, but would break the OBS plugin, the MCP server, scripts and `examples/drive_the_api.py` until they are updated. *Default:* the existing API stays open; only the new plugin-manager routes (install, update, enable, remove) require the desktop app's per-session secret, and plugin credentials are checked on the new plugin endpoints.
5. **Do you want a human "Reviewed" tier one day, and who would review?** *Default:* no such tier; "Listed" means automated checks only, and the UI says so.
6. **Who merges registry pull requests?** *Default:* you, with CI doing all the checks it can.
7. **Should Clips Kitty's own modes appear in the Marketplace as Official pipelines?** This is the dogfooding step: Shorts, Gaming and the Sports pipelines described by manifests, not moved. *Default:* yes, as read-only "built in" entries.
8. **Should there be an official "Open Shorts for Clips Kitty" adapter?** It needs Docker (WSL 2 on Windows) or a reachable Open Shorts instance, and the hosted Open Shorts sends media off the machine ([note](platform/research-notes/clipping-pipelines.md)). *Default:* designed as the worked example of a third-party pipeline, not built tonight.
9. **For remote pipelines, confirm once per plugin or before every job?** *Default:* a warning on the listing and at install, plus a confirmation the first time a job would send media, remembered per plugin and shown on every job card.
10. **Opt-in usage counts, ever?** *Default:* none; only GitHub stars and release downloads captured at index build.
