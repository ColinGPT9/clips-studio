# Game engines: Godot, Unity, Unreal/Fab

- Platforms: Godot Asset Store + editor plugins; Unity Package Manager (UPM) + Asset Store; Unreal Engine plugins + Fab
- Tier: 3 (one short section per platform)
- Date read: 2026-10-06
- Track C question: what makes an extension ecosystem successful, and what mistakes should Clips Kitty avoid?

Verdict: All three engines use a tiny declarative descriptor (plugin.cfg, package.json, .uplugin) plus a folder convention, and all three run plugin code with the editor's full privileges; none has a permission model. Their stores differ mainly in money and review: Godot is free and human-reviewed in beta, Unity sells through a reviewed store beside an open npm-style registry layer, and Fab is a paid, reviewed marketplace with an 88/12 split.

---

## Godot (Asset Store, May 2026; editor plugins)

1. Unit: an editor plugin = a folder `addons/plugin_name/` with `plugin.cfg` and a `@tool` script that `extends EditorPlugin` (GDScript) or `[Tool]` + `EditorPlugin` (C#); "any other GDScript that your plugin uses must also be a tool script". Also GDExtension (native shared libraries), templates and other assets via the store. (making_plugins.html, read 2026-10-06)
2. Manifest: `plugin.cfg`, INI format, section `[plugin]` with exactly these keys in the docs' example:
   ```
   [plugin]
   name="My Custom Dock"
   description="A custom dock made so I can learn how to make plugins."
   author="Your Name Here"
   version="1.0"
   script="custom_dock.gd"
   ```
   `version` is a free string (the docs recommend semantic versioning). No engine-compatibility field in the file; compatibility lives on the store listing: "For each version you upload you can give it a name, write a changelog, and specify the minimum Godot version (and maximum if applicable)." (submitting_to_asset_store.html)
3. Distribution/install: the store runs at store.godotengine.org; assets download into the project from the editor's "Asset Store" main-screen tab (templates from the Project Manager); versions are uploaded files, "Each individual version has a maximum file size of 1GB" (the old Asset Library pointed at Git repositories; the new store hosts files: the Foundation had to "re-upload all assets from the Asset Library to the new hosting solution as the Asset Library doesn't actually host any of the assets it distributes"). Nothing runs at install; the plugin runs when enabled in Project Settings > Plugins. Guidelines reject "Standalone, compiled executables" and "NuGet files"; "Any shared library files listed in a .gdextension file must be present." (what_is_asset_store, submitting_to_asset_store, store guidelines, article; read 2026-10-06)
4. Dependencies/isolation: none. Everything lives in the project under `addons/<name>/` "to prevent file conflicts"; plugins share the editor process and project. No dependency declaration (not confirmed in the pages read).
5. Versioning: "Multiple download versions per asset", per-version changelog and min/max Godot version; `version` string in plugin.cfg. Rollback = download an older version (inferred). The Asset Library "should be considered deprecated, and will be set as a read-only repository in the near future" (article 2026-05-22).
6. Registry: central, run by the Godot Foundation, closed source ("The store's source code remains private" per the docs page, bug tracker public), "currently in beta"; unified Godot account; publishers get analytics; "fully integrated in Godot 4.7". Submission is a web form; every submission is human-reviewed: "You will be informed when your asset is reviewed. If it was rejected, you will be told why that may have been, and you will be able to submit it again." Requirements: "The asset must work" in the stated Godot version, `LICENSE`/`LICENSE.md` with copyright, proper English, 16:9 icon, no joke/low-effort submissions, no empty zips. Cost: Foundation-hosted web app plus reviewers (no figures published).
7. Trust/permissions: no permission model; plugin scripts run with editor privileges (inferred from the plugin model). Review is a functional and formatting checklist, not a security review. No "verified" tier seen.
8. Models: none.
9. Local (in editor). Remote: n/a.
10. Incidents/limits: "beta", "various pain points, bugs, and usability issues"; "While paid assets can't be uploaded yet" (donation links allowed); migration from Asset Library is manual: "Assets have not been moved over to the new Asset Store automatically." No incidents on the pages read (not confirmed).
11. Borrow: per-version compatibility range entered at publish time (min required, max optional) and shown per download; multiple live versions with changelogs; the one-folder-per-plugin rule that makes conflicts obvious.
12. Avoid: shipping a store with no dependency field and no machine-checkable manifest beyond name/version; relying on a closed-source backend when a static index would do (Clips Kitty has no Foundation to host one); forcing a manual migration by changing the hosting model after launch.
13. Sources (read 2026-10-06): https://godotengine.org/article/introducing-the-godot-asset-store/ (post date 2026-05-22); https://docs.godotengine.org/en/stable/tutorials/plugins/editor/making_plugins.html ; https://docs.godotengine.org/en/stable/community/asset_store/submitting_to_asset_store.html ; https://docs.godotengine.org/en/stable/community/asset_store/what_is_asset_store.html ; https://store.godotengine.org/guidelines/ .

Matrix row:
`| Godot Asset Store | Editor plugin folder addons/<name>/ with plugin.cfg + EditorPlugin script; GDExtension; templates | None | None | Central store run by Godot Foundation (closed source, beta), replaced the Git-link Asset Library in May 2026 | No (uploaded files, 1 GB per version; old Asset Library linked Git repos) | Yes | n/a | Many versions per asset, each with min/max Godot version; plugin.cfg version free-form | No permission model; human review of each submission ("must work", licence file, no executables) | Free only today; paid "on the roadmap" | Per-version engine range at publish time; one folder per plugin |`

Lesson for Clips Kitty: Godot proves a store can launch without a manifest richer than name/version because the store form carries compatibility — but that makes compatibility unverifiable offline. Put `min/max host version` in the manifest, not the form.

## Unity (UPM scoped registries + Asset Store)

1. Unit: a UPM package (folder or tarball with `package.json`), or a `.unitypackage` from the Asset Store.
2. Manifest: `package.json`. Required: `name` ("A unique multi-part identifier that conforms to the Unity Package Manager naming convention, which uses reverse domain name notation", e.g. `com.company.my-package`) and `version` ("must respect Semantic Versioning"). Recommended: `description`, `displayName`, `unity` ("Indicates the lowest Unity version the package is compatible with", `major.minor` e.g. `2022.3`), `unityRelease` (e.g. `0b4`). Optional: `dependencies` (map of package name to SemVer version), `keywords`, `author` (name/email/url), `license` ("SPDX identifier format"), `licensesUrl`, `documentationUrl`, `changelogUrl`, `samples` (displayName/path/description), `hideInEditor`, `type` ("Reserved for internal use"). (upm-manifestPkg.html, read 2026-10-06)
3. Distribution/install: the project's `Packages/manifest.json` lists `dependencies` as name → version, local path (`file:<path>`), tarball, or Git URL (`"https://my.repository/my-package.git#v1.2.3"`); `scopedRegistries` entries have `name`, `url`, `scopes` (`["com.company"]`). "the Package Manager compares the package name to the scopes values and finds the registry whose scopes value is the closest match"; no match → default registry. Registries are npm-compatible (auth via `npmAuth` in `.upmconfig.toml`), so a scoped registry is any npm-protocol server, self-hostable. Install = download/extract; C# compiles in the editor; nothing else runs at install (inferred). (upm-manifestPrj.html, upm-scoped.html, upm-scoped-use.html, upm-config-scoped.html)
4. Dependencies/isolation: one project-wide package set; dependency resolution with `resolutionStrategy` (`lowest` default, `highestPatch`, `highestMinor`), `enableLockFile` (default true), `pinnedPackages` ("use the exact package version specified ... even if a different package version is more compatible with your version of the Unity Editor"). Conflicts are resolved by SemVer rules in one graph, not isolated per package.
5. Versioning: SemVer required; lock file; pinning; `unity`/`unityRelease` minimum compatibility; Git URLs can pin a tag/commit with `#`.
6. Registry: default Unity registry + any number of scoped registries (no review; "Organizations often use scoped registries as a mechanism to distribute custom packages within the organization"). The Asset Store is a separate, curated, paid marketplace: "The Asset Store team reviews each package draft to make sure it meets the submission guidelines before you can publish"; "The Asset Store team takes at least five business days to analyze your submission. If you don't receive a response after two weeks, contact the Unity support team." Submission guidelines last updated 2026-05-20: new assets must target Unity 2022.3 or newer; `.unitypackage` max 6 GB, UPM products max 700 MB; no executables (`.exe`, `.apk`), no DRM/registration walls/paywalls (except SaaS SDKs), no obscuring compressed files, AI-assisted content must be disclosed. UPM products can also be sold through the Asset Store ("Submit a UPM product for approval"). (docs.unity.com asset-store pages, submission guidelines; read 2026-10-06)
7. Trust/permissions: none at runtime. Official warning: "Install scoped registries only from trusted sources, because the packages in those registries can contain executable code" and watch for "third-party registries that might be harmful or capture data without appropriate controls" (upm-scoped-use.html). Asset Store review is quality/compatibility/marketing review, not sandboxing.
8. Models: none.
9. Local. Remote: n/a.
10. Incidents/limits: none on the pages read (not confirmed). Revenue share: a 70/30 publisher split appears only in search snippets and a 2012 Unity blog that now returns 404; not confirmed on a current official page. Payouts are documented (monthly PayPal or quarterly bank transfer, USD only, 2FA mandatory).
11. Borrow: reverse-DNS package names with scope-prefix routing to registries; SemVer + lock file + explicit `pinnedPackages`; Git URL with `#tag` as a first-class install source (this is Clips Kitty's "GitHub at a pinned ref" already); the explicit trust warning on third-party registries; a `unity` minimum-host-version field with an optional finer `unityRelease`.
12. Avoid: a single project-wide dependency graph where two plugins fight over one package version (Clips Kitty's frozen runtime cannot even do this; per-plugin isolation is the only option); a review queue measured in weeks for a free registry; no upper compatibility bound in the manifest (Unity has only a minimum).
13. Sources (read 2026-10-06): https://docs.unity3d.com/Manual/upm-scoped.html ; https://docs.unity3d.com/Manual/upm-manifestPkg.html ; https://docs.unity3d.com/Manual/upm-manifestPrj.html ; https://docs.unity3d.com/Manual/upm-scoped-use.html ; https://docs.unity3d.com/Manual/upm-config-scoped.html (authentication only); https://docs.unity.com/en-us/asset-store/llms.txt ; https://docs.unity.com/en-us/asset-store/publishing/asset-packages/submit.md ; https://docs.unity.com/en-us/asset-store/publishing/upm-packages/submit.md ; https://docs.unity.com/en-us/asset-store/publishing/asset-packages/revenue/payouts.md ; https://assetstore.unity.com/publishing/submission-guidelines (last updated 2026-05-20); https://unity.com/blog/en/2012/04/07/tutorial-how-to-publish-and-make-money-on-the-asset-store/ — 404, not confirmed.

Matrix row:
`| Unity UPM + Asset Store | UPM package folder/tarball with package.json; .unitypackage | None | None | Default registry + self-hosted npm-compatible scoped registries (no review) beside a curated paid Asset Store (human review, >=5 business days) | Yes for install (Git URL with #tag in manifest.json); registries are npm servers | Yes | n/a | SemVer required; lock file; pinnedPackages; resolutionStrategy; unity min version only | No runtime permissions; official warning that registry packages "can contain executable code"; store review is quality, not security | Asset Store paid (70/30 not confirmed on a current page) | Reverse-DNS ids + scope routing; Git-URL pinning; lock file |`

Lesson for Clips Kitty: keep the open, uncurated layer (scoped registries, Git URLs) and the curated layer (store) separate and say plainly which one you are in; Unity's "can contain executable code" warning is the honest default for any non-reviewed source.

## Unreal Engine plugins + Fab

1. Unit: a plugin folder under `[Project]/Plugins/[Name]/` or `Engine/Plugins/[Name]/` with a `[Name].uplugin` descriptor, optional `Source/` (C++ modules with `.Build.cs`), `Binaries/`, `Intermediate/`, `Content/`, `Config/`, `Resources/Icon128.png`. "Unreal Engine finds your Plugin by searching for .uplugin files on disk." Plugins are enabled per project in the Plugin Browser / `.uproject`. (plugins-in-unreal-engine, read 2026-10-06)
2. Manifest: `.uplugin`, JSON, "a JSON-formatted list of variables from the FPluginDescriptor type". `FileVersion` is "the only required field in the structure" ("currently, this is 3"). Example fields: `Version` (int, "Version number for the plugin"), `VersionName` ("1.0"), `FriendlyName`, `Description`, `Category`, `CreatedBy`, `CreatedByURL`, `DocsURL`, `MarketplaceURL`, `SupportURL`, `EnabledByDefault`, `CanContainContent`, `IsBetaVersion`, `Installed` ("Signifies that the plugin was installed on top of the engine"), `Modules` (each needs `Name` and `Type` from Runtime, RuntimeNoCommandlet, Developer, Editor, EditorNoCommandlet, Program; plus `LoadingPhase`). From the API reference: `EngineVersion` ("Version of the engine that this plugin is compatible with"), `Plugins` (array of FPluginReferenceDescriptor: `Name`, `bEnabled` → "Enabled", `bOptional` → "Optional" "the game should silently ignore it not being present", `Description`, `MarketplaceURL`, platform/target allow and deny lists, `RequestedVersion` "specifies a specific version of the plugin that this references"), `bIsExperimentalVersion`, `SupportedTargetPlatforms`, `bExplicitlyLoaded`, `PreBuildSteps`/`PostBuildSteps`. Boolean JSON keys drop the leading `b`. (FPluginDescriptor and FPluginReferenceDescriptor API pages, read 2026-10-06)
3. Distribution/install: copy the folder into `Plugins/`; code plugins compile with the project (UBT) or ship precompiled binaries ("compile your plugin with Visual Studio 2019 — the minimum supported version for UE 5.2" for binary compatibility). Fab: "To upload your Unreal Engine files, you must provide a Project File Link to a hosting website (such as Google Drive, Dropbox, or OneDrive). These files must be available for download and not require login information." as a `.zip`; "Code Plugins must contain at least one code module." Fab delivers through the Epic Games Launcher (inferred; not on the pages read). `PreBuildSteps`/`PostBuildSteps` mean a plugin can run commands at build time.
4. Dependencies/isolation: declared in `Plugins[]` with Enabled/Optional/RequestedVersion; "Plugins and Modules are broken into hierarchical levels, and can only depend on other Plugins or Modules at the same level or higher." All modules load into one process; no isolation.
5. Versioning: `Version` int + `VersionName` string; `EngineVersion`; on Fab each uploaded file is tagged with engine-version checkboxes, and sellers can "Add compatibility for new engine versions to files that already exist without providing new files" — except code plugins, which "Always require an updated project to be submitted, even if the plugin works as expected in the latest engine release." Binary plugins must be rebuilt per engine version (documented via the VS-version note).
6. Registry: Fab, Epic-run, central, paid-or-free listings. Flow: create listing → "Submit it to the Fab team for review" → the team "checks your listing to ensure that it meets the content and technical requirements" → publish (auto or manual). "If you edit a live listing, Fab creates a duplicate listing that goes through moderation. Your original listing remains live during moderation." Seller onboarding: Fab account, Distribution Agreement, Creator Code, "Trader Verification", tax and payout setup. Revenue: "You will receive 88% of the revenue generated by your product sales"; paid ~30 days after month end once ≥ $100 USD. The documentation landing page ("industry-leading 88% revenue share") mixes documentation with marketing language. What Fab replaced: press (CGPress, 2024-09-17) says Fab unified "Unreal Engine Marketplace, Sketchfab, ArtStation Marketplace, and Quixel" and went live mid-October 2024 with "an 88/12 revenue split for creators"; the official Fab doc page I read says only "Fab is Epic's open marketplace" and "does not replace the Fortnite Item Shop or the Epic Games Store"; Epic's own blog post on the launch returned 403 — the replacement claim is press-sourced here. The fab.com seller/about pages returned 403 (marketing pages, not read).
7. Trust/permissions: none at runtime; a plugin is native code in the editor and game process. Fab review checks that products function and meet "content and technical requirements"; it is a quality gate, not a security gate (inferred from the pages read).
8. Models: none.
9. Local. Remote: n/a.
10. Incidents/limits: none on the pages read (not confirmed). Limits: per-engine-version rebuilds for code plugins; zip hosted on third-party drives during review.
11. Borrow: dependency references as data (`Plugins[]` with `Name`, `Enabled`, `Optional`, `RequestedVersion`) so a missing optional dependency fails soft; `EnabledByDefault` and explicit enable per project; `IsBetaVersion`/`IsExperimentalVersion` flags surfaced in the UI; re-moderating edits to a live listing while keeping the old one live.
12. Avoid: build hooks (`PreBuildSteps`) that let a plugin run arbitrary commands at install/build time; binary compatibility that forces every plugin to be rebuilt per host release (Clips Kitty's frozen runtime makes this a real risk for native wheels; prefer pure-Python plugins over the local API); reviewing by hand before every publish for a free registry — Fab can afford it on 12%.
13. Sources (read 2026-10-06): https://dev.epicgames.com/documentation/en-us/unreal-engine/plugins-in-unreal-engine ; https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Projects/FPluginDescriptor ; https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Projects/FPluginReferenceDescriptor ; https://dev.epicgames.com/documentation/en-us/fab/publishing-assets-for-sale-or-free-download-in-fab ; https://dev.epicgames.com/documentation/en-us/fab/asset-file-format-and-structure-requirements-in-fab ; https://dev.epicgames.com/documentation/en-us/fab/publisher-get-started-in-fab ; https://dev.epicgames.com/documentation/en-us/fab/fab-documentation (documentation with marketing wording); https://dev.epicgames.com/documentation/en-us/fab/content-you-can-sell-on-fab — loaded empty, not confirmed; https://www.fab.com/sellers and https://www.fab.com/about — HTTP 403, not read (marketing); https://www.unrealengine.com/blog/fab-content-marketplace-launches-in-october-publishing-portal-opens-today — HTTP 403, not read; press: https://cgpress.org/archives/epic-games-to-launch-fab-unifying-its-digital-content-marketplaces-in-october.html (2024-09-17).

Matrix row:
`| Unreal plugins + Fab | Plugin folder with .uplugin JSON (C++ modules and/or content) | None | None | Fab, Epic-run central marketplace (replaced UE Marketplace, Sketchfab, ArtStation Marketplace, Quixel in Oct 2024 per press) | No (zip via a Drive/Dropbox "Project File Link"; delivered via launcher) | Yes | n/a | Version int + VersionName; EngineVersion; per-file engine-version tags; code plugins must resubmit per engine release | No runtime permissions; native code; Fab human review of every listing and of every edit to a live listing | Paid; 88/12 | Plugins[] dependency references with Optional + RequestedVersion; beta/experimental flags; re-moderate edits without taking the old listing down |`

Lesson for Clips Kitty: Fab shows what full human review costs — it is paid for by a 12% cut and a seller-verification pipeline. A $0, 0% registry cannot fund that; it must get the same assurance from automated checks, pinned refs and an honest "not reviewed" label.

## Hypotheses (engines)

- H1: all three run plugins in-process with full privileges and none claims otherwise; Unity's docs say registry packages "can contain executable code". Supports H1 by contrast (inferred).
- H3: Unity shows Git URLs pinned by `#tag` and self-hosted registries work with zero platform involvement; Godot and Fab both chose hosted uploads instead and both need a funded backend and reviewers. Supports H3.
- H4: Unity (≥5 business days), Godot (beta, manual), Fab (every listing and every edit) all review by hand; only Fab explains how it pays for it. Supports H4's cost claim; no evidence here on automation.
- H5: no engine has declared permissions at all, so nothing to enforce; the honest pattern is Unity's blanket warning. Consistent with H5.
- H6: Unity resolves one shared graph with lock file + pinning; Unreal rebuilds per engine version; Godot has no dependency model. Supports "one shared env invites conflicts" (Unity has to ship resolutionStrategy and pinnedPackages to manage it).
- H8: Unity's reverse-DNS names with scope routing is a working namespacing precedent; Unreal's `Plugins[]` references with `Optional` show dependency-as-data. Supports H8's namespacing half; no typed capabilities anywhere.
- H9: Fab's 88/12 and Unity's (unconfirmed) 70/30 bracket the "stated share" market; Clips Kitty's 0% is outside this market by decision.
- H10: Godot's store offers "Analytics for publishers" (hosted downloads make counts free); Unity and Fab count sales server-side. Supports H10: counts come from the host, which a static Git registry does not have.
