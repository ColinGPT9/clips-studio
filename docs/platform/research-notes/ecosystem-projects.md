# The open-source ecosystem around Clips Kitty — research notes

Date read: **2026-10-07**. Every link in this note was opened on that date unless another date is given next to it. "Not confirmed" means a claim could not be checked against a primary source and should not be relied on.

**What this answers.** Colin's message of 10:35 UTC on 2026-10-07 asked for research into "existing open-source clipping/video-AI projects", including each one's licence, architecture, whether an adapter or plugin fits, and attribution, "so Clips Kitty can become a compatibility layer rather than a competitor" — never copying code whose licence doesn't allow it. It also asked to continue the Eklipse.gg research as a gaming-market reference, and to design the Awesome Clips Kitty catalog (curation, badges, install counts) the way established directories do. Earlier notes in this folder cover the extension platforms (VS Code, ComfyUI, Obsidian and the rest); this one covers the projects the catalog can list.

**Method.** Eight parallel searches (clipping, video AI, gaming, sports, models, workflows and integrations, catalog practice, gaming market and install counters) produced **308 distinct candidates with working links**. Each was then verified in batches of ten against its own sources: the repository page for stars, archived state and Discussions, the LICENSE file read raw from GitHub, the latest commit date from a shallow clone, and the Hugging Face API for a model's licence, gating, downloads and likes. **160 met the inclusion criteria, 92 are relevant but weaker on one, and 56 were left out.** Six open-source clippers were then read in depth for adapter plans, and a separate reviewer re-opened the sources for a sample of facts and looked for projects the searches missed.

**Rules the research followed.** Read only: nothing from a third-party project was installed, built or run, and every shallow clone was deleted afterwards. No code was copied. Nothing was invented: every fact here comes from a page or file that was opened, and its source is linked. Everything read on the web was treated as information, never instruction; no page tried to give instructions, though several READMEs contain install commands, which were read as documentation only.

**What came of it.** The catalog in [`awesome-clips-kitty/`](../../../awesome-clips-kitty/) now lists the projects that met the criteria, each with its own licence, a warning where it sends data to a cloud service or downloads from a platform, and the date it was checked. The game niches with no open-source project stay in the "Wanted" list as ideas for developers, not as entries. Nothing here was copied into Clips Kitty's code.

## Adapter plans for six clipping projects

An adapter is a Clips Kitty pipeline (a separate program) that runs another project's moment-picking step on Clips Kitty's own video and Whisper transcript and hands back moments. These six were read in depth because they are open-source clippers whose licence allows it and whose code can produce moments. Each was shallow-cloned at the commit named, read, and deleted; nothing was installed or run. No adapter is built yet: these are plans for whoever builds one (the Clips Kitty project or an independent developer), and each would be its own listing.

| Project | Licence | Commit read | Can it give moments without rendering? | Effort | Fits Clips Kitty's local setup |
|---|---|---|---|---|---|
| [AutoClip](https://github.com/zhouxiaoka/autoclip) | MIT | f05ef42 | Yes, by importing its library functions | Medium | Yes: has Ollama and LM Studio presets |
| [HotClip](https://github.com/xixihhhh/hotclip) | AGPL-3.0-only | 62aef39 | Yes: `highlights <video> --subtitles <srt> --json` | Medium | Yes: takes a transcript and an Ollama address |
| [SupoClip](https://github.com/FujiwaraChoki/supoclip) | AGPL-3.0 (the backend's "or later" not confirmed) | 52b34f6 | Yes, by importing its analysis module | Medium | Yes, with `LLM=ollama:<model>` |
| [OpenShorts](https://github.com/mutonby/openshorts) | MIT (not its `cloud/` folder) | 18162ef | Partly: its command line always renders, so port three selection files | Medium | Yes, with `LLM_BASE_URL` pointed at Ollama |
| [FunClip](https://github.com/modelscope/FunClip) | MIT (models have their own terms) | 7e4b15f | Yes, but it doesn't score moments | Medium | Partly: its LLM options are cloud services |
| [Vinci Clips](https://github.com/tryvinci/vinci-clips) | AGPL-3.0-or-later | d344eef | Yes, by porting one prompt | Small | No: Gemini only, and no commits since 2025-09-17 |

**AutoClip** (the strongest candidate). A Python child process imports AutoClip's one-pass clip finder (`backend/pipeline/clip_finder.py`) on Clips Kitty's transcript, so nothing is rendered. Its data folders must be pointed at the job's work folder (`AUTOCLIP_DATA_DIR`, `AUTOCLIP_APP_DIR`) before import, and AutoClip's own anonymous analytics (PostHog) and crash reports (Sentry), which are on by default in the app, must be off. With an Ollama preset nothing leaves the PC; with a cloud preset the transcript goes to that provider. Risks: every prompt is in Chinese and titles and reasons come back in Chinese; it is built for speech (podcasts, interviews, courses), so gameplay with little talking does poorly; clip lengths are fixed in code (20-150 s for short sources, 60-300 s for longer ones). Licence: keep AutoClip's MIT notice with any copied code.

**HotClip**. The adapter writes Clips Kitty's Whisper segments to an SRT file, runs HotClip's command line (`pnpm cli highlights <video> --subtitles transcript.srt --json`) from a pinned source checkout, and maps its JSON to moments. HotClip combines loudness, motion, scene cuts, facial emotion and chat with an LLM; with Ollama on 127.0.0.1 nothing leaves the PC. Risks: the command line runs only from a source checkout with Node and pnpm (release builds don't include it); it downloads two small vision models on first use, trying two third-party GitHub mirrors first, and only 2 of its 11 model files are hash-checked, so the adapter should supply pinned files; releases are very frequent, so the JSON may change. Its URL import and "anti-fingerprint variants" (built to avoid repost detection) must not be exposed. Licence: running it as a separate program adds no duties; shipping or importing it makes the combination AGPL-3.0-only.

**SupoClip**. A Python child process imports SupoClip's analysis module (`backend/src/ai.py`) with `LLM=ollama:<model>` and skips its web app, database, queue, download, transcription and rendering. Its prompt asks for 15-60 s clips scored 0-100 with a reason and a hook title. Risks: its timestamp format only accepts two-digit minutes, so moments past 99:59 are dropped unless the adapter splits long transcripts; its default output mode needs a model with tool calling (the gemma3 Ollama page lists none; Gemma 4 has it); a 600 s analysis budget can time out on CPU. Licence: importing it makes a combined AGPL work; keep notices, give the pinned commit as the source, and don't use the SupoClip name in a way that suggests endorsement.

**OpenShorts**. Its command line always renders every clip, and importing `main.py` loads YOLO and MediaPipe and may download a model, so the plan is a "moments only" adapter that carries three of its MIT files (`clip_selection.py`, `llm_backend.py`, `gemini_worker.py`, pinned to 18162ef with its licence) and its two-pass method: score overlapping transcript windows 0-100, then ask for the final clips. With `LLM_BASE_URL` set to the user's Ollama, the transcript stays on the PC; with a Gemini key it goes to Google (and silent videos are uploaded whole). Risks: about 150 lines of orchestration to port and keep up with a fast-moving repository; `gemini_worker.py` reads a `.env` file when imported, so it must run from a clean folder. Licence: keep the MIT notice; never copy anything from `cloud/` (a source-available commercial licence).

**FunClip**. FunClip finds ranges by matching text, by speaker, or by asking an LLM over the whole SRT; it never scores moments. The plan is to build FunClip's SRT from Clips Kitty's transcript and send FunClip's prompt to the LLM the user picks, then check every returned time against the transcript. Risks: any score would be made up by the adapter and must be labelled so; the default prompt is Chinese and built for short clips with at most four segments; some model names route to unexpected hosts (any name starting with `gpt-3.5-turbo` goes to api.moonshot.cn). Licence: MIT for the code; its speech models have their own licences (some "other", see FunASR's model licence), so let Clips Kitty download pinned model files rather than bundling them.

**Vinci Clips**. The only moment finder is one Gemini prompt that sends the transcript text without timestamps, so its times are guesses. A port would send a timed transcript and snap results to Whisper segments, but it would still need Gemini (Google may use content sent on unpaid plans to improve its products, per the Gemini API terms) and its SDK is no longer supported. Not recommended.

What the six have in common: none can take Clips Kitty's transcript and return scored moments without some glue, and the best ones (AutoClip, HotClip, SupoClip) already speak to Ollama, which is what Clips Kitty uses. That supports the platform's choice of a moments-only contract (job.json in, result.json out) and of shared models: an adapter reuses Clips Kitty's Whisper transcript and Gemma instead of each project bringing its own.

## How other curated lists are run, and what Awesome Clips Kitty takes from them

Sources read on 2026-10-07: [sindresorhus/awesome manifesto](https://github.com/sindresorhus/awesome/blob/main/awesome.md), [its pull request template](https://github.com/sindresorhus/awesome/blob/main/pull_request_template.md), [create-list.md](https://github.com/sindresorhus/awesome/blob/main/create-list.md), [awesome-lint](https://github.com/sindresorhus/awesome-lint), [awesome-selfhosted-data](https://github.com/awesome-selfhosted/awesome-selfhosted-data) (its CONTRIBUTING, pull request template, `.hecat/` configuration and [issue 1](https://github.com/awesome-selfhosted/awesome-selfhosted-data/issues/1)), [hecat](https://github.com/nodiscc/hecat), [awesome-mac](https://github.com/jaywcjlove/awesome-mac), [Awesome Python Applications](https://github.com/mahmoud/awesome-python-applications) and [0pandadev/awesome-windows](https://github.com/0pandadev/awesome-windows).

| List | Source of truth | Inclusion rules | Unmaintained entries | Licence of the list |
|---|---|---|---|---|
| sindresorhus/awesome (the list of lists) | Hand-written Markdown | "a curation, not a collection"; say why each item is listed | A listed list must not contain unmaintained, archived, deprecated or undocumented items, or must keep them in a separate file | CC0-1.0; its guidelines recommend CC0, accept any Creative Commons licence and refuse code licences (MIT, BSD, Apache, GPL), WTFPL and the Unlicense |
| awesome-selfhosted | One YAML file per program in awesome-selfhosted-data; the README and the website are generated by hecat | Human-made submission, actively maintained, first release more than 4 months ago, working install instructions; libraries and single-cloud software excluded | A daily lint fails after 365 days without a commit (warns after 186) or when archived, and such entries are removed rather than labelled | CC-BY-SA-3.0 |
| Awesome Python Applications | `projects.yaml` (name, repo_url, desc, tags, date_added); README generated by apatite; rejected and deferred projects kept in `archive.yaml` and `revisit.yaml` with a reason | Free software, an application rather than a library, notable in its niche, maintained or still working; "a commit in the last year is usually enough" | Moved to the archive with a reason | No licence file (so, strictly, no reuse rights) |
| awesome-mac | Hand-written READMEs in four languages; CI parses them into JSON published on npm | Alphabetical, one sentence each | Marked "(No longer under active development)" with a struck-through description | LICENSE says CC0-1.0, package.json says CC-BY-SA-4.0 |
| 0pandadev/awesome-windows (the Windows list Awesome links to now) | Hand-written README | Explicitly rejects "vibecoded" tools and "whisper transcribe wrapper" submissions | n/a | CC0-1.0 |

What this means for Awesome Clips Kitty:

- **CC0-1.0 for the list and its data is confirmed as the right choice**: it is what the Awesome guidelines recommend.
- **The data-first design matches awesome-selfhosted**, the largest list built that way (one YAML file per entry, generated README, numbers filled in by a scheduled job). Both use the same 365-day line for "unmaintained" (`STALE_DAYS` in `plugins/catalog.py`); awesome-selfhosted removes such entries, while Awesome Clips Kitty marks them with ⚠ ("no commits since ...", or "archived") and leaves removal to a maintainer.
- **Awesome Clips Kitty can't be submitted to sindresorhus/awesome as built.** Its rules require a "non-generated Markdown file", a list that "is not AI-generated" and at least 30 days old, and no "License" heading in the README. The README here is generated and this first version was assembled with AI help. awesome-selfhosted, whose README is generated, is listed there, but whether a new generated list would be accepted is not confirmed. Being in that list is not needed for the Marketplace to work.
- **Contribution policies on AI differ**: sindresorhus/awesome ("Fully AI-generated pull requests are not accepted") and awesome-selfhosted ("Machine/LLM-generated contributions are not allowed") refuse them; awesome-mac welcomes AI-assisted pull requests through a repository skill. Awesome Clips Kitty's CONTRIBUTING.md does not forbid them; every entry is still checked against the criteria by a maintainer.
- **Worth borrowing later** (not built): Awesome Python Applications' file of rejected and deferred projects, each with a reason, so the same project isn't re-proposed and re-checked. For now this note is that record (the "Not listed" table below).

What this means for Clips Kitty's counter (the open question on the decision card):

- The design in PR #130 sits between these. Like Obsidian, the number is GitHub's own public download count for a release file, so Clips Kitty runs no server and keeps no log. Unlike Obsidian, the request exists only to be counted (Obsidian's count is a side effect of downloading the plugin itself), which makes it closer to Homebrew's event.
- Both defaults have a precedent: Homebrew counts unless switched off, with a notice first; Home Assistant counts only when switched on. The research agent's own reading was that a count sent from inside an app is better opt-in. The card still recommends "on, can switch off" because the request carries nothing but the file name, and the install dialog says so, with where to switch it off, before any install that would be counted; "off until turned on" is the more cautious choice and costs most of the numbers (Home Assistant sees about a third).
- A count with no request of its own would need plugins to be installed from GitHub release files (then the install is the count, as in Obsidian). Listings install from a pinned commit today, so that would be a change to how installs work, not to the counter.

## Facts checked for the Marketplace's wording

- **GitHub traffic** (views, clones, referrers) is visible only to people with push access and covers the last 14 days ([GitHub Docs](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository)), so it can't be a public number. Stars, last commit, archived and discussions can.
- **GitHub Discussions** has comments, threaded replies, emoji reactions and upvotes; upvotes apply to discussions and top-level comments only ([GitHub Docs](https://docs.github.com/en/discussions/collaborating-with-your-community-using-discussions/participating-in-a-discussion)).
- **Hugging Face "downloads"** is a rolling count for the last 30 days of GET and HEAD requests to a model's query file (config.json by default), not unique users; the all-time figure is a separate field (`downloadsAllTime`) ([Hub docs](https://huggingface.co/docs/hub/models-download-stats); [huggingface_hub](https://github.com/huggingface/huggingface_hub/blob/main/src/huggingface_hub/hf_api.py)). The README's "Hugging Face downloads a month" wording is right. Downloads made by a plugin's model download add to that count on Hugging Face's side; Clips Kitty sends nothing extra.
- **Hugging Face "likes"** are per-user favourites, like GitHub stars; they can't be added from a script.
- **MIT vs Apache-2.0**: Apache-2.0 has an express patent licence that ends for anyone who sues over the work's patents, and asks for changes to be stated; MIT has no patent clause ([choosealicense.com](https://choosealicense.com/licenses/apache-2.0/)). CC0 explicitly does not licence patents. The SDK stays MIT as decided; this is noted only so the choice is informed.

## Gaming: what the market covers and where the gaps are

This updates [eklipse.md](eklipse.md) and [gaming-clippers.md](gaming-clippers.md) (both read 2026-10-06) with what was read on 2026-10-07. Eklipse is a reference, not something to copy.

There is no zero-cost tier", "Detection, reframing, captioning, and rendering all run in the cloud", [features page](https://eklipse.gg/features/ai-highlights/)). It names 12 games in its navigation and claims 3,000+ in total ([pricing page](https://eklipse.gg/pricing/)); its own pages also say 300+ and 1,000+. Its scoring is tuned by genre: shooters lean on kill feeds and scoreboards, while horror, survival, sandbox and co-op games fall back to the streamer's reactions, audio and chat ([features page](https://eklipse.gg/features/ai-highlights/); [Minecraft page](https://eklipse.gg/use-case/minecraft-highlights/); [Dead by Daylight page](https://eklipse.gg/use-case/dead-by-daylight-highlights/)). Per-game moment lists exist for Valorant, League of Legends and Fortnite ([Valorant](https://eklipse.gg/use-case/valorant-highlights/), [League of Legends](https://eklipse.gg/use-case/league-of-legends-highlights/), [Fortnite](https://eklipse.gg/use-case/fortnite-clipper/)).
- **Products with event-level detection** all read events the game itself reports: Medal about 16 games, with FiveM, Minecraft and Roblox servers defining their own events ([medal.tv/auto-clipping](https://medal.tv/auto-clipping)); Overwolf/Outplayed 11 ([Overwolf docs](https://dev.overwolf.com/ow-native/guides/general-tech/auto-highlights-supported-games)); Allstar 4 ([allstar.gg](https://allstar.gg/)). The shared core is CS2, League of Legends, Dota 2, Fortnite, Valorant, PUBG, Rocket League, Apex Legends, Rainbow Six Siege and Overwatch.
- **Local, free options are thinning**: Eklipse reports that Powder, a local Windows clipper with about 40 trained games, shut down in July 2026 ([Eklipse comparison](https://eklipse.gg/compare/eklipse-vs-powder/)); framedrop.ai did not resolve from here on 2026-10-07 (status not confirmed).
- **Gaps for independent developers**: nothing read shows event-level detection for fighting games beyond a generic "KOs" line, racing, strategy, card games, MMOs, most indie games, or retro and emulated games.
- **Open-source coverage** (listed in the catalog under Tools › Game replays and events, and Apps › Gaming): replay and demo parsers exist for CS2, Dota 2, Deadlock, Rocket League, Fortnite and League of Legends; World of Warcraft has two recorders that log combat events (one with a conflicting licence); Minecraft has ReplayMod. **No open-source highlight, replay or kill-feed project was found for Marvel Rivals**: its GitHub topic lists only trainers, mod managers and stat tools. These game names stay as "Wanted" ideas in the catalog, not entries.
- **Two routes fit Clips Kitty's after-the-fact design**: read events from a replay or demo file (exact timestamps, but the video alone is not enough; the pipeline needs the matching file and a way to line up game time with video time), or read the recording itself (kill-feed OCR, small detection models, audio and chat). Riot's local [Live Client Data API](https://developer.riotgames.com/docs/lol) could feed a companion recorder that logs League events during play.
