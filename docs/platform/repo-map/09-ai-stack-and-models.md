### How a backend is chosen (`llm/registry.py:14-52`, `create_backend(llm_config: dict) -> LLMBackend`)
1. `spec = llm_config["backend"]`; `provider, _, model = spec.partition("/")`.
2. `provider == "ollama"` -> `OllamaBackend(model, host=llm_config.get("ollama_host","http://localhost:11434"), temperature=llm_config.get("temperature",0.4), num_ctx=llm_config.get("num_ctx",8192))` (`llm/registry.py:18-26`).
3. `llm.signin.catalog.is_signin(provider)` -> `signin.get(provider, llm_config["data_dir"]).backend(model, llm_config)` (`llm/registry.py:28-37`).
4. `llm.providers.catalog.get(provider)` -> `CloudBackend(spec, model, data_dir)` (`llm/registry.py:39-50`).
5. else `ValueError("Unknown LLM provider ...")` (`llm/registry.py:52`).

`llm_config` comes from `main.py:68-115 load_config`: the flat `model:` key in `config/settings.yaml:5` becomes `config["llm"]["backend"] = "ollama/<model>"` unless it already has a slash (`main.py:75-78`); `CLIPS_STUDIO_OLLAMA_HOST` env overrides `llm.ollama_host` (`main.py:102-104`); `config["llm"]["data_dir"] = config["paths"]["data_dir"]` (`main.py:113`). Other llm keys: `translation_model`, `temperature: 0.4`, `num_ctx: 8192`, `ollama_host` (`config/settings.yaml:35-46`).

Call sites: `core/pipeline.py:431`, `server/jobs.py:432`, `server/api.py:1653`, `server/api.py:2783`, `longform/process.py:111`; all but one wrap it with `_with_usable_model(config["llm"])` (`core/pipeline.py:141-163`), which for a local spec swaps in `llm.manager.resolve_usable_model` so the backend names a model Ollama actually has (cloud specs pass through untouched).

### OllamaBackend (`llm/ollama_backend.py`)
- `__init__(model, host="http://localhost:11434", temperature=0.4, num_ctx=8192, timeout=600)` (`:49-64`).
- `generate`: POST `{host}/api/generate` with `{"model","prompt","stream":False,"options":{temperature,num_ctx,"num_predict":1024}}`, plus `"format":"json"` when `json_mode` (`:66-80`, `:110`).
- `look`: same endpoint with base64 `images`, `format: json`, `num_predict: 512`, `think=False` if model has "thinking" capability (`:86-101`).

- Reasoning-model handling `_limit_reasoning` (`:126-156`): setup models (RECOMMENDATIONS minus gemma4*) untouched; `_THINK_TO_ANSWER = {"gpt-oss": "medium", "nemotron": True}` keep thinking, `num_predict=6144`, no `format`; `_ANSWER_WITHOUT_FORMAT = ("gemma4",)` get `think=False` and no `format`; other thinking models get `think=False`.

## 7. Open questions for the platform work

1. Ollama model store is owned by the Electron main process (`OLLAMA_MODELS`, `ui/src/main/index.ts:150-163`), not by the Python engine; a shared model manager that wants to index Ollama blobs must either read `OLLAMA_MODELS` or keep using `/api/tags` (`llm/manager.py:136`). The Docker/checkout cases use whatever Ollama is at `llm.ollama_host`.
2. YOLO weights have no fetch script and no hash; in a checkout ultralytics downloads them on first use to the working directory (`core/binaries.py:135-137`, `:150-153`). Which ultralytics release/asset is implied is not written anywhere in the repo (inferred).
3. Whisper weights are referenced by size name only; the size -> HF repo mapping lives inside faster-whisper (`scripts/fetch_whisper.py:92-94`), so there is no revision pin in the repo.
4. TalkNet weights are pulled from third-party HF mirrors at `resolve/main` with a size floor only (`scripts/fetch_asd_model.py:23-28`); no hash is verified.
5. `models/` and `vendor/` are gitignored and absent in this checkout (`ls` showed neither), so every local non-LLM model path is build-time state. No runtime manifest lists what was bundled; `core/preflight.py` only checks ffmpeg, Ollama, Whisper, GPU, disk (`:298-331`), not PANNs/ASD/voice/YOLO.
6. The frozen-build resolvers disagree in shape: `core/binaries._search_roots` (several roots incl. `_internal/<folder>`) vs. `sys._MEIPASS/<file>` direct in `analysis/panns.py:48-49`, `video/asd.py:83-84`, `analysis/voice_turns.py:105-106`. A shared manager would need one path policy.
7. Capability flags exist for cloud models (`ModelInfo`) and Ollama (`/api/show capabilities`), but nothing records VRAM need per local model beyond `RECOMMENDATIONS` prose (`llm/manager.py:31-43`).
8. ChatGPT plan runtime (openai-codex) is "Not in the Store build or the installer yet" (`llm/signin/chatgpt.py:22-23`); its install path and availability check (`ChatGPTPlan.available`, `:188`) were not read in detail.
9. `_with_usable_model` silently re-points a local backend at any installed Ollama model (`core/pipeline.py:141-163`); a plugin that expects a specific model must account for that.
