- `docs/EXTENDING.md:9-11` — "If you want to build something *beside* the app rather than change it ... You probably want [API.md] instead. The whole pipeline is already reachable over HTTP."

## 2. Design rules (ARCHITECTURE.md section 15, `ARCHITECTURE.md:997-1021`)

Quoted verbatim:
- "**Stages communicate only through dataclasses and files.** The analyzer never touches video; the tracker never reads transcripts." (`ARCHITECTURE.md:1001-1002`)
- "**`analysis/` depends on `llm/base.py` only**: never on a concrete backend." (`:1003`)
- "**`sources/` and `publish/` are plugin folders.** Adding a platform means adding one file; nothing downstream changes." (`:1004-1005`)
- "**Learned data can never degrade output.** Every score contribution derived from accumulated knowledge is additive, capped, deterministic, and individually disableable." (`:1006-1008`)
- "**The LLM proposes, deterministic code disposes.** Parsing, validation, duration enforcement, deduplication, and edit application are all plain Python, so a model swap changes quality but never correctness." (`:1009-1011`)
- "**Failure is contained.** Optional subsystems: creator learning, chat replay, heatmaps, signal prefetch: are wrapped so that a failure degrades a feature instead of breaking a run." (`:1012-1014`)
- "**Prompts are editable text.** Tuning behaviour should not require writing code." (`:1015`)
- Scaling path: "The state DB and file-artifact handoff between stages mean stages can later become queue workers ... without redesign. The contracts between stages don't change." (`:1017-1021`)

Related rules stated elsewhere:
- `ARCHITECTURE.md:452-456`: "`registry.py` maps a config string to a backend. Nothing in `analysis/`, `creator/`, or `multilingual/` imports a concrete backend".
- `ARCHITECTURE.md:939-942`: "Prompts are data, not code ... `config/gaming.yaml` ... and `config/sports.yaml` ... are data in the same way."
- `sports/__init__.py:9-11`: "It adds no pipeline of its own. The sport's profile plugs into the same scoring the gaming profile uses (analysis/fusion.py), with the same Whisper, the same AI (any provider), the same renderer, queue, watches and publishing."
- `analysis/intent.py:16-22`: "It only ever ADDS ... Nothing is lowered or removed and the scoring prompts never see it".

## 5. Open questions (for the platform design)

1. `publish/` is called a plugin folder but has no name→publisher table; `server/publisher.py:29` hardcodes `youtube_service`. Which lookup would a third-party publisher plug into? (inferred gap)
2. `sources/dispatch.py` has no table at all (if-chain). A registry there would be new code, not an extension of an existing one.
3. All data tables (`config/*.yaml`, `config/prompts`, `gaming/layouts.json`) load from fixed repo/bundle paths; no user-data overlay exists. Does the platform add an overlay dir under `resolve_data_dir()` (`core/paths.py:18`)?
4. The frozen build imports by allowlist (`clips-studio.spec:53`); in-process third-party Python would have to be loaded from outside the bundle, which no existing code does.
5. UI mirrors several engine tables by hand (gaming layouts, vertical numbers, prompts: `tests/test_ui_gaming_layout_sync.py`, `tests/test_web_vertical_sync.py`, `tests/test_web_prompt_sync.py`); any registry a plugin extends must be served over the API instead of mirrored.
6. The API has no auth (`docs/API.md:77`); an out-of-process plugin has the same access as the desktop app, which matches BRIEF H5 only if scoping is added at the API boundary.
